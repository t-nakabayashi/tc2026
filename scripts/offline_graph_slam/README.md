# つくば2026のRTK拘束なしオフライン・グラフSLAM

入力は `/media/nkb/TEST/tc2026_20261004_full_course_manual_logging_merged`。
出力は `/media/nkb/TEST/graph_slam_20261004`。元bagはSQLite読取専用で開く。
ROSノード・センサドライバ・走行指令は起動しない。

## 処理

`extract.py` が測定UTC、記録済みFAST-LIO raw姿勢、GNSS品質、IMU等を抽出する。
追加の12:36走行も観測値だけ抽出するが、地図・評価に使用しない。
`build_keyframes.py` は全コースのraw LIOを時刻ギャップ10秒超、逆行、位置跳躍2 m超で4区間に分ける。
各区間の冒頭20秒のIMU（角速度ノルム0.15 rad/s未満）をLIO座標で平均的に整列し、
重力方向を鉛直にする。重力はyawを決定しない。実機の独立した姿勢校正ではない。

移動1.2 m・回転12度・経過5秒のいずれかでキーフレームを選び、
有効Livox tag、0.8〜65 mの点を抽出する。点ごとの時刻でraw LIOを内挿して歪みを補正し、
0.15 mのボクセルで間引く。0.3秒超の姿勢欠測を跨ぐスキャンは使わない。
公称LiDAR→IMU並進と取付角・主アンテナレバーアームは `common.py` に明記してある。
FAST-LIOはbagに記録された結果を使用し、生IMUからのFAST-LIO全再実行は行わない。

`solve_graph.py` はキーフレーム前後2枚以内・12秒以内のサブマップを作り、GICPで中断部を接続する。
中断直前・直後の車体が近いという時系列の事前情報から初期化し、必要ならyaw候補を試す。
GNSS位置・方位・受信状態を読み込まず、点群で接続を判定する。
接続条件は収束、両方向の0.5 m以内対応率62%超、前方向最近傍中央値0.23 m未満、
Hessian最小/最大固有値比1e-6超。3接続を採用。
追加の逆方向チェックでは往復並進差は0.006〜0.027 m、回転差0.022〜0.109度。
1接続の逆方向中央値0.239 mは再訪ループの厳しい中央値条件0.23 mを超えるが、
接続に用いた前方向中央値は0.192 mで、両方向対応率・往復変換の整合性は成立する。

ループ候補は接続済みLIO軌跡の18 m近傍から、60秒超・累積移動60 m超離れた再訪を選ぶ。
上記の点群条件に加え、初期値から15 m・35度以内、逆方向GICPも採用条件を満たし、
往復差0.15 m未満・1度未満を要求する。候補239組から14拘束を採用。
`refine_loops.py` が最適化後の軌跡の12 m近傍を同じ条件で1回再探索し、264候補から2拘束を追加する。
これらの候補選択、重み、閾値にはGNSSを使わない。

グラフはSE(3)。2,179姿勢、2,175相対移動、3接続、16再訪、1初期姿勢事前分布を含む。
相対移動因子の標準偏差は距離・時間に応じて設定する。
接続・再訪は並進0.1 m、回転0.3度、Huber定数1.345。
GTSAM Levenberg-Marquardtで最適化し、GNSS因子は0件。
重みと採用条件は精度を保証するものではない。

## RTKとの評価

`evaluate_map.py` はグラフ最適化完了後に初めてGNSSを読み、アンテナ位置で比較する。
品質とfixの時刻差0.05秒未満、FIX状態4、補正齢2秒未満、衛星10以上、HDOP 2以下を良好FIXとする。
各キーフレーム間の補正変換を内挿してraw LIOへ適用し、GNSS時刻の姿勢を得る。
グラフの4区間を跨ぐ補間、0.3秒超のLIO欠測を跨ぐ補間、外挿を行わない。

二つの座標合わせを区別する。

- 冒頭180秒の876良好FIXで水平剛体整列し、それ以後の8,611良好FIXを評価する。
  評価側のRTK位置を座標変換の推定へ渡さない。閉合後RMSE 6.443 m、95%点8.163 m。
- 全9,487良好FIXで水平剛体整列し、同じFIXと軌跡形状を比較する。
  スケール・形状は変えない。閉合後RMSE 0.314 m、95%点0.773 m、最大0.970 m。
  座標合わせと評価の観測を共用するため独立評価ではない。

各方式でLIOとSLAMを同じ観測集合で別々に整列する。`fit_xy` はsoft-L1、尺度0.3 mのロバスト整列。
全FIX整列で必要な追加yawはSLAMで約0.897度。最初の短い区間だけの地理合わせと、
全コースの軌跡形状の評価は異なる結果となる。どちらも独立した真値に対する絶対精度ではない。

停止の長さの影響を抑えるため、SLAM累積距離の1 m区間ごとに良好FIXを一つだけ抽出する。
未使用FIXの307地点でRMSE 5.030 m、全FIX整列で0.311 m。
状態別統計は場所・時間が異なるので、状態だけに起因する誤差とは判定しない。
10/30/60秒の同一区間・良好FIX端点間の移動量差もJSONに出力する。

地図は観測した環境の点群。遮蔽・未収録領域を補完しない。動体除去・自由空間判定・
自律走行用のoccupancy map化、別走行での自己位置推定、実機走行は未検証。
デジタルツイン参照線の全1,142点が地図軌跡から10 m以内だが、これは精密測量の検証ではない。

PC内パスはiPhoneから直接開けるURLではない。会話内画像と要約を閲覧版とし、

## 再実行と異常時

ROS Jazzyの既存メッセージ型と、専用venvのGTSAM 4.2.1、NumPy 1.26.4、
既存small_gicp 1.0.1、SciPy、Matplotlib、PyYAMLを使う。
PDFには既存実験runtimeのreportlabを使う。OSや実機launchを変更しない。

```bash
bash /home/nkb/colcon_ws/scripts/offline_graph_slam/run.sh
OPENBLAS_NUM_THREADS=1 /home/nkb/.cache/tc2026-graph-slam-venv/bin/python3 -m pytest \
  -c /home/nkb/colcon_ws/scripts/offline_graph_slam/pytest.ini \
  /home/nkb/colcon_ws/scripts/offline_graph_slam/test_numerics.py
```

`run.sh` は抽出キャッシュを使い、派生成果物を同じ出力先へ再生成する。
入力や設定を変える場合は`common.py`と`extract.py`の出力先を新しい専用ディレクトリへ変える。
キーフレーム生成中断時は元bagを変更せず、未完成の派生キャッシュを分離して再実行する。
中断接続またはループが成立しない場合は例外で停止する。部分出力を完成地図として扱わない。
長い欠測は自動的に除外・区間分離し、欠測中の地形や軌跡は生成しない。

数値試験3件は時刻内挿と外挿拒否、ENUと剛体整列、GNSSなし合成閉ループの改善を確認する。
PDFはPopplerで全ページをPNGへレンダリングして目視確認した。
