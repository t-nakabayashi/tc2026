# 外部NTP → PC → PTP → MID360 評価（2026-09-23）

## 判定

構成として有望。GNSS USB到着時刻をPCの時計基準から外し、GNSS測位データには受信機の測定UTCを保持できた。
ただし3分間で点群タイムスタンプの微小逆行2件があり、現行の厳格な監視でゲートが20標本失効した。
通常走行の連続安定性は未合格。逆行を許すような閾値緩和は行っていない。
独立時刻基準との測定ではないため、絶対精度が実証されたとは扱わない。

## 構成・試験条件

ユーザーがevaluate-ntp.shをsudoで適用。chronyの既存外部NTPプールを使用し、
UM98 SOCKはnoselectで比較のみ。サービスのdrop-inでclock-source=ntpを指定した。
PCはslew補正を維持し、LiDARへsoftware PTPを配信。車輪・LIO・融合は起動しない。
GNSSドライバのみtime_sync.enabled=trueでRMC比較サンプルを供給したが、PC時刻源には選択されない。

NTP試験ゲートは選択源^*、直近応答成功、鮮度2ポーリング周期以内（上限256秒）、正常Leap、
残補正5 ms以下、|残補正|+root delay/2+root dispersionが20 ms以下を要求。
20 msは試験用の開始条件であり、10 ms絶対精度要件を満たすという意味ではない。
NTP応答喪失からの停止時間はGNSS版の8秒基準とは異なる。ネットワーク断の故障注入は未実施。
PC同期が収束してからPTPが開始し、生パケット条件が成立した後の180秒を記録した。

## 結果

- chrony36標本の推定誤差上限：7.037〜17.913 ms、最後7.315 ms。
- 残補正の絶対値最大：1.560 ms。基準NTP源の切替あり。
- 点群375,127パケット、IMU36,000パケット。すべてtime_type=1（PTP）。
- カーネル受信時刻との差99%点：点群1.793 ms、IMU0.614 ms。
- 点群逆行2回：約13.6 µs、6.7 µs（浮動小数点UTCから算出した近似値）。IMU逆行なし。
- 逆行した2組はUDP連番がそれぞれ48830→48831、12355→12356。受信順序の逆転では説明できない。
- ゲート成立：160/180標本。NTP条件やPTP配信の喪失ではなく、逆行後10秒の抑止が作用。

chronyの推定誤差はUSB RMC基準時の約100 msより小さい。ただしUSB RMCには設定precision=0.1秒が含まれ、
この数値比較のみから真の精度改善量は決められない。USB RMC基準とNTPの差は引き続き約37〜40 ms。
生パケット受信差は伝送・生成遅延を含み、LiDAR時計の独立した偏差測定ではない。

## GNSS測定時刻と融合の確認

stamp_source=gnss_utc、transport_delay_ms=0。
ドライバはGGAの測定時分秒と新鮮なRMCの日付からUTCを構成し、NavSatFix等のheader.stampへ保持する。
chronyの選択元をNTPへ変更してもこの測定UTCは変更されない。
融合はheader.stampで並べ、0.35秒の遅延バッファと測定時刻におけるLIO内挿を使用する。
GNSS ROS記録は240秒・2,400件、時刻逆行なし。受信時刻−測定時刻は中央値36.862 ms、
99%点198.652 ms、最大202.575 msで、全標本が現設定の0.35秒バッファ内だった。
今回融合自体は起動しておらず、連接はコード確認。GNSS ROS受信記録はgnss_stamps.jsonを参照。

## 残課題と終了時の設定

次は微小逆行の発生源（LiDAR内PTPサーボ・時刻出力処理など）とFAST-LIOへの影響を調べる。
ネットワーク断・長時間のNTPサーバ切替も未試験。回線条件によりNTP精度は変わる。
NTP評価設定は適用済みのまま保持し、測定用GNSSノードは終了する。
外部NTPとPTPサービスは継続し、次の共通起動でもNTP条件で監視される。
以前のGNSS基準へ戻す場合は、走行停止中に同梱restore-gnss-after-ntp.shをsudoで実行する。
通常のinstall_clock_service.shは外部NTPを既定とする。GNSS基準の比較試験を行う場合は、試験用設定と通常設定を明示して切り替える。
変更後の自動試験92件成功、2パッケージのcolconビルド成功。

[chrony公式の誤差上限の説明](https://chrony-project.org/doc/4.4/chronyc.html)
に従った推定であり、上流基準の正しさを仮定する。

## 通常起動への変更（評価後のユーザー指定）

PCの同期基準を外部NTPに確定。サービス既定・通常インストーラ・共通起動ゲートをNTPへ統一した。
GUIの実機／実機（融合）の手動・自律プリセットは共通bringupへ接続する。
GNSSの測定UTC保持・RMC noselectは維持し、0.1 ms以下の微小逆行は回数記録だけとする。
比較基準を過去最大時刻とし、微小逆行の累積が閾値を超えた場合も検出する。
既存の180秒評価の2イベントはいずれも新しい許容範囲内だが、新設定での再測定結果とは区別する。
GUIプリセットを含む105試験成功、対象2パッケージのビルド成功。OSサービスの反映には通常インストーラ適用が必要。

通常インストーラ適用後、chrony/icart-clockがenabled・active、NTP指定、RMC noselect、
LiDAR IP=192.168.1.201、微小逆行許容0.1 msの実配置を確認した。
配置コードのSHA256はリポジトリと一致し、点群・IMUともready=true。
normal_service_applied.jsonに適用確認時点の状態を保存。GUIからの実車起動・走行は実施していない。
