# 自律走行の位置推定評価

評価日: 2026-09-27。対象: コミット `6b34e8f` のソース、共通実機起動、生成設定、保存された評価記録。
本評価はコード確認、既存自動試験、人工入力による再現試験である。実車は起動・走行していない。

## 判定

GNSSの絶対位置・方位、LiDAR/IMUの相対移動、車輪による退避を組み合わせる構成は合理的である。
時刻整合、取付補正、重力整列、異常観測の棄却、速度制限も実装されている。
ただし、方位入力の鮮度と異常後の復帰に再現可能な問題がある。現状を、実機で精度・継続性が
確認された自律走行用位置推定とは評価できない。優先順位は方位鮮度の保証、相対運動の復帰、
現在の構成での実測評価である。

## 現在の処理の流れ

1. 記録ルート走行のGUI入口は `recorded_route.launch.py`。走行用セッションを生成し、
   `bringup.launch.py` を実機モードで使用する。実際の値は各セッションのYAMLに依存する。
2. GNSSとMID-360を起動し、外部NTP → PC → software PTP → MID-360の同期成立を待つ。
   GNSSの観測stampは受信機UTCを保持する。共通起動の時計ゲートはNTP状態と生パケット監視を使う。
   運用中の同期条件喪失はlaunch全体を終了させ、再開には利用者の再起動を要する。
3. MID-360点群とIMUをFAST-LIOへ入力する。FAST-LIOはオンラインの局所地図と照合し、
   `/lio/odometry_raw` を出す。この起動には保存済み地図への再局在やループ閉合の接続はない。
4. `gravity_alignment_node` が約2秒の静止IMU・LIO・車輪データから鉛直基準を確定する。
   固定回転を位置・姿勢・pose共分散へ適用し、`/lio/odometry` を出す。
   IMU取付角とIMU位置のレバーアームは、その後の融合で車軸中心へ補正する。
5. UM982の緯度経度高度を経路と共通のENU原点へ変換する。受信機の北基準・時計回り方位を
   mapの反時計回りyawへ変換し、主アンテナ位置を車軸中心へ補正する。
6. 融合は0.35秒の遅延バッファで観測を時刻順に処理し、GNSS時刻へ相対姿勢を内挿する。
   MotionGuardが通常LIO、異常・不整合・短い途絶時に車輪の相対変位を選ぶ。
   平面状態 `[x, y, yaw]` を予測し、GNSS位置と方位を分離して補正する。
7. バッファ内の最新相対姿勢まで予測した `/localization/pose_enu` をroute_followerと
   robot_navigatorが利用する。GNSS単独の `/gnss/pose_enu` は別出力である。
   navigator → `/cmd_vel/autonomous` → 融合の速度制限 → `/cmd_vel/fusion_limited`
   → 自律・手動mux → 車輪ドライバの順で制御する。

## 座標・品質・異常時の条件

- 現在のハードウェア設定はアンテナ間隔0.15 m、主アンテナが車軸から後方0.30 m、
  主アンテナ高さ0.564 m。MID-360取付はroll -0.6°、pitch 26.9°、yaw 0°。
  IMU原点はLiDAR内部の外部パラメータから生成し、LiDARの高さ0.414 mとは区別する。
- 共通起動の方位補正は180°。ENU原点と地図回転は経路と一致させる。
  単体融合の基線長既定0.5 mを、そのまま現在の実機設定と扱ってはいけない。
- 基線長・衛星数・FIX/FLOAT・方位標準偏差により重みと採否を決める。
  初期化はFIX、8衛星以上、方位σが0より大きく15°以下等を要求する。
  基線長学習のready確定そのものは初期化の必須条件ではない。
- 位置観測σの下限はFIX 0.15 m、FLOAT 3 m。ただし実機ドライバはHDOPから共分散を作り、
  融合はその値が下限より大きければ採用する。これらは実測精度でも精度保証でもない。
- GNSS補正量は位置0.5 m/s、yaw 0.12 rad/sを上限とする。最大0.1秒分ずつ補正するため、
  低頻度観測では実時間あたりの補正速度はさらに下がる。
- 良好時の速度上限は1.1 m/s、低信頼時0.6 m/s、位置σが1 m以上なら0.25 m/s、
  車輪退避中は最大0.4 m/s。位置不確かさだけでは停止しない。
- 重力基準待ち・初期FIX待ち・出力が1.5秒超古い場合、融合は自律指令を0にする。
  navigatorにもpose/odomの受信途絶1秒、muxにも自律指令途絶0.5秒の監視がある。
  これらの設定値から実車の制動距離は認定できない。
- 共通起動でraw LIOが1.5秒超途絶すると重力基準を破棄し、融合も初期化をやり直す。
  車輪だけで無期限に継続する構成ではない。新しい静止基準とFIXが必要になる。

## 指摘事項

### 優先度1: 古いGNSS方位が新しい観測として流れる

`um982/client.py:get_position` は最新GGAとキャッシュ済みUNIHEADINGを結合するが、
両者の時刻差を検査せず、出力timestampにGGAの時刻だけを使う。
`driver_node.py:_on_position` はその時刻をfix/statusへ共通設定する。
従ってROS側のstamp一致は、位置と方位の同時観測を保証しない。

人工入力で位置stamp=1000、方位stamp=900を与えると、100秒古い方位90°とσ=1°が
FIXの位置stamp=1000に結合されることを確認した。方位文だけが途絶しても、位置文が続けば
この状態を検出できない。旋回時に古い方位で推定を引き戻し、方位σを過小評価する可能性がある。

対応案: 方位の観測時刻・鮮度・解品質を入力境界で保持し、位置との時間差を検査する。
方位だけの途絶試験と旋回中の異時刻試験を追加する。GNSS全体を遮断するR1試験では代用できない。

### 優先度2: 相対運動を採用できない一回の入力から自動復帰できない

`motion_guard_core.py:select` は入力ごとの基準を更新した後、採用変位がなければ
融合側stampを更新せずreturnする。次回は入力基準stampと融合stampが一致しないため、
正常な差分も計算対象から外れ続ける。

人工入力では0.2秒に車輪欠測、0.3秒にLIOジャンプと車輪復帰を与えた。
0.4～5.0秒に両入力を正常化してもNO_MOTIONが継続し、採用stampは0.2秒のままだった。
下流は出力鮮度監視で停止する方向だが、重力整列のリセット等が起きない限り自然復帰できない。

対応案: 入力を再び差分計算できるよう基準を確立する処理と、未観測移動の扱いを明示する。
姿勢を架空に更新せずに復帰する試験を追加する。

### 評価上の制約

- LIOの判定は主に移動量・時間・車輪との整合であり、点群照合の退化や残差は融合へ入力しない。
  車輪スリップ時に正しいLIOを棄却する可能性と、両入力の共通誤差が残る。
- GNSSの2本のアンテナが同方向へずれる誤差は、正常な基線長だけでは検出できない。
  良好と判定したFIXが継続すると、大残差でも再取得する。
- 方位差45°超の自動再取得はLIO異常後に限定される。緩やかな方位漂流でこの差を超えた場合の
  無条件再初期化はない。位置σ中心の減速だけで走行領域内に留まれるとはいえない。
- 不確かさによる指令縮小は並進速度から算出するため、並進0のその場旋回は同じ機構では減速しない。
- map/odomの二層化による補正隔離はなく、GNSS補正を含むmap姿勢を直接追従制御に使う。
- 重力整列ノードは確定後も時刻の近いIMU・車輪入力を要求する。センサの独立した冗長性には制約がある。

## 検証結果と証拠の範囲

- 関連6パッケージの既存試験: 220成功、1失敗（10.20秒）。実行結果は `pytest_results.txt`。
  失敗は `test_icart_middle_calibration_and_three_layers_agree`。
  navigatorの角加速度0.6 rad/s²とドライバ1.5 rad/s²の同値検査で失敗する。
  実行時の契約は「要求値がドライバ上限以下」なので、これだけで走行不能とは判定しない。
  テストの意図と設定の整合を確認する必要がある。
- 既存の隔離ROS途絶試験: 初期FIX待ち、LIO途絶中の車輪継続、全相対入力途絶後の指令0を確認。
  `dropout_results.txt`。この試験は重力整列を要求しない単体FusionNodeを使うため、
  共通実機起動の長いLIO途絶からの復帰試験にはならない。
- 追加の問題再現: `probe.py` と `probe_results.json`。ROSや車輪を起動しない人工入力試験。
- 2026-09-23の保存された実機時刻評価では、GNSS ROS受信2400件の受信遅延最大は約203 msで、
  0.35秒バッファ内。現在は外部NTP基準、微小逆行許容0.1 msの設定が記録されている。
  適用時のready確認はあるが、現在の構成による長時間の融合走行精度の証明ではない。
- 保存済み全周模擬評価 `log/codex/fusion_trial/full_route/fusion_review.json` は
  融合RMSE約1.67 m、最大約9.77 m、経路横ずれ最大約3.76 m、±1 m内約77.2%。
  基線長約0.5 m等の条件が現行実機と異なるため、現在の精度値には流用しない。
- 本評価では実車の精度、制動、閉ループ完走は未検証。確認時に車輪・LIO・融合の実行プロセスはなく、
  時計サービスのreadyもfalseだった。これは位置推定精度の成否を示す観測ではない。
