# <規約名>

規約を新規作成するときの雛形。配置は `docs/` 直下とする。

規約は個別の事例ではなく判断の原理を与える文書である。読み手が未知のケースに
直面したときに自力で判断できる状態にする。

## 1. 目的

- この規約が無いと何が起きるかを書く。規約の存在理由が読み手に伝わる状態にする。
- 適用範囲（どのパッケージ、どの種類の対象に効くか）を明示する。

## 2. 定義

- 規約が扱う対象の分類を定める。以降の規則はこの分類ごとに書く。
- 分類の境界が曖昧になる例があれば、どちらに倒すかを決めておく。

## 3〜n. 規則

- 分類ごとに規則を書く。**各規則に理由を添える。** 理由の無い規則は守られない。
- **個別対象の一覧表を作らない。** 一覧表は実装から必ず乖離する。個別の性質は対象
  そのもの（`.msg` の先頭コメント、設定ファイルのコメント）に宣言させ、規約は
  導出規則だけを持つ。

## n+1. 例外

- 既定から外れる対象と、その理由を書く。
- 例外を認める条件を書く。条件の無い例外は既定を空文化させる。

## n+2. 手順

- 新しい対象を追加するときに踏む手順を書く。
- 規約への適合を機械的に検査できる場合は、検査方法と実行コマンドを書く。
