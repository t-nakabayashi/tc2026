# <package_name>

運用手順（パッケージ `README.md`）を新規作成するときの雛形。

読み手が手順どおりに実行すれば動く状態にする文書である。**README に設計を書かない。**
設計は詳細設計書へ置き、README からリンクする。300 行を超えたら設計の混入を点検する。

## 1. 概要

- このパッケージが何をするかを 3 行以内で書く。

## 2. 前提

- 依存パッケージ、必要なハードウェア、事前設定を書く。
- 実機が必要な手順と、模擬環境で完結する手順を区別する。

## 3. ビルド

- ビルドコマンドを書く。`docs/` を install 対象にしている場合は、文書の改名・削除後に
  `build/<package_name>/` のクリーンが要ることを書く。

## 4. 起動

- 代表的な起動方法を書く。構成が複数ある場合は、それぞれの用途を 1 行で添える。
- 実機ドライバを起動する手順を含む場合は、安全上の前提を明記する。

## 5. パラメータ

- **利用者が変更しうるものだけ**を表で書く。全パラメータの列挙は詳細設計書の役割である。
- 名前、型、既定値、単位、変更時に何が変わるかを書く。

## 6. 確認方法

- 動いていることをどう確かめるかを書く。確認コマンドと、期待する出力を書く。
- 自動確認できない項目は、確認していない範囲として明示する。

## 7. 関連文書

- 詳細設計書、上位のアーキテクチャ設計、関連パッケージの README へリンクする。
- `docs/notes/` の検討資料へはリンクしない。参照は検討資料から恒久文書への一方向とする。
