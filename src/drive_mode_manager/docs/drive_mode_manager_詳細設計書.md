# drive_mode_manager 詳細設計書

## 1. 目的・スコープ

本書は `drive_mode_manager` パッケージの内部設計を定める。対象ノードは 4 つである。

| ノード | 役割 |
| --- | --- |
| `manual_teleop_node` | Joy 入力から手動速度指令を作る |
| `drive_cmd_mux_node` | 自律指令と手動指令を選び、最終速度指令を配信する |
| `drive_status_gui_node` | 走行モードと指令の状態を表示する |
| `ps3_joy_sim_node` | キーボード入力から Joy を作る（開発用） |

トピック名、型、パラメータの一覧と起動方法は [README](../README.md) を正とする。
`ps3_joy_sim_node` の鍵割り当てと内部仕様は
[ps3_joy_sim 設計書](ps3_joy_sim_設計書.md)を正とする。本書は残る 3 ノードについて、
**状態遷移の条件、出力の決定規則、入力鮮度の判定、安全側の挙動と制約**を定める。

最終速度指令の配信元を 1 つに集約し、自律走行と手動操縦のどちらが車体を動かすかを
明示的に管理する。責務は次の 4 点である。

- Joy 入力を手動速度指令へ変換する。
- 自律・手動のモードを保持し、Joy 操作で切り替える。
- モードと入力鮮度に応じて、最終速度指令として自律指令・手動指令・ゼロのどれを出すかを
  決める。
- 判断に使った入力の状態を外部へ通知する。

非スコープは、速度・加速度の物理的な制限（`ypspur_ros2` が担う）、障害物による減速
（`robot_navigator` と `gnss_lio_fusion` が担う）、経路追従である。

**本パッケージは物理的な非常停止回路の代替ではない。** ソフトウェアの状態遷移で指令を
止める仕組みであり、電源遮断やモータ出力の物理的な切断は行わない。

**手動指令は自律側の融合減速・障害物監視を通らない。** 手動操縦中は、障害物や位置品質に
よる速度の縮小が一切かからない。

記載内容はすべて実装済みである。実コントローラの番号割り当てと実機での制動性能は
確認範囲が限られる（9.3 節）。

## 2. 構成とファイル配置

```text
/joy ──→ manual_teleop_node ──→ /cmd_vel/manual ──┐
                                                   ├──→ drive_cmd_mux_node ──→ /cmd_vel
/cmd_vel/autonomous ───────────────────────────────┘           │
/joy ─────────────────────────────────────────────────────────→┘
                                                               ↓
                                                      /drive_mode_status
                                                               ↓
                                                     drive_status_gui_node
```

`/joy` は `manual_teleop_node` と `drive_cmd_mux_node` の両方が購読する。前者は軸から
速度を作り、後者はボタンからモード遷移を判定する。**同じ Joy メッセージを 2 つのノードが
独立に時刻付けする**ため、2 つのノードの鮮度判定は厳密には同期しない。

ROS 非依存のロジックを 3 モジュールへ分ける。

| モジュール | 対応ノード | 責務 |
| --- | --- | --- |
| `manual_teleop_core.py` | `manual_teleop_node` | 軸の読み出し、不感帯、反転、倍率 |
| `drive_mode_core.py` | `drive_cmd_mux_node` | モード遷移と出力選択 |
| `gui_core.py` | `drive_status_gui_node` | 表示モデルの生成と逆算 |

共通起動では mux の自律入力を `/cmd_vel/fusion_limited` へ remap する。最終速度指令の
配信元を mux 1 つに保ち、融合減速を経た指令を自律側として扱うためである。

| パス | 用途 |
| --- | --- |
| `drive_mode_manager/*_node.py` | 4 ノードの ROS 層 |
| `drive_mode_manager/*_core.py` | ROS 非依存ロジック 4 モジュール |
| `launch/drive_mode_manager.launch.py` | Joy 入力源・teleop・mux・任意の GUI をまとめて起動 |
| `launch/ps3_joy_sim.launch.py` | Joy simulator の単独起動 |
| `params/default.yaml` | 4 ノード分の既定パラメータ |
| `tests/` | ROS 非依存ロジックの単体試験 |

## 3. 外部インタフェース仕様

一覧は [README](../README.md) を正とする。本章は一覧に現れない取り扱いと、QoS の選定
理由を定める。

### 3.1 QoS

既定のプロファイル（RELIABLE / VOLATILE / KEEP_LAST）を使い、深さのみ指定する。

| 対象 | 深さ | 選定理由 |
| --- | --- | --- |
| `/cmd_vel`、`/cmd_vel/autonomous`、`/cmd_vel/manual` | 1 | 古い指令を溜めず最新値だけを扱うため |
| `/joy`、`/drive_mode_status` | 10 | — |

### 3.2 `/cmd_vel`（mux の配信）

**配信周期ごとに無条件で配信する。** 出力がゼロの場合もゼロの `Twist` を配信する。
配信を止めることはない。下流が「配信の途絶」を安全状態として検出する設計にはなって
いない。

`linear.x`、`linear.y`、`angular.z` のみを設定する。他のフィールドは 0 である。

**ノード終了時にゼロの `Twist` を 1 回配信する。** 終了処理で最後に安全値を出す。
配信の失敗は無視する。

### 3.3 `/cmd_vel/manual`（teleop の配信）

配信周期ごとに無条件で配信する。デッドマン解放、Joy 途絶、軸の範囲外、非有限値の
いずれでもゼロを配信する。

### 3.4 `/drive_mode_status`（mux の配信）

判断に使った入力の状態をすべて含める。各フィールドの意味は
[DriveModeStatus.msg](../../tc_route_msgs/msg/DriveModeStatus.msg) を正とする。

モードと出力元は**別のフィールド**である。自律モードでも出力元はゼロになり得る
（6.3 節）。

### 3.5 Joy と速度指令の時刻

**Joy の鮮度は `header.stamp` ではなく受信時刻で判定する。** `manual_teleop_node` と
`drive_cmd_mux_node` のどちらも、メッセージを受け取った時点の ROS 時刻を記録する。
Joy ドライバ側の遅延や、古い stamp を持つメッセージの再配信は検出しない。

速度指令の鮮度も同様に受信時刻で判定する。`Twist` は stamp を持たないため、他に判定の
手段がない。

### 3.6 画面・可視化

`drive_status_gui_node` が PyQt5 で走行状態を表示する。

| 表示 | 内容 |
| --- | --- |
| モード | 自律（緑）/ 操縦（黄）の色分け |
| 出力元 | `ZERO` / `AUTONOMOUS_CMD` / `MANUAL_CMD` |
| 理由 | 状態通知の理由文字列 |
| 最終指令 | 前後速度と角速度 |
| 復帰予定 | 復帰待ち中の残り秒と、復帰後に出る予定の指令の方向（7.5 節） |
| 入力状態 | Joy の有無、L1 の押下、各指令の鮮度 |
| RTK 状態 | `rtk_gps_um982_msgs/RtkStatus` の要約 |
| Waypoint 状態 | `/follower_state` の要約 |
| route manager 状態 | `/manager_status` の要約 |

描画領域は 16:9 に収めて中央へ配置する。`main_display_ratio`（既定 0.70）で主表示と
副表示の比率を決める。

**GUI は表示専用である。** 操作入力を受け付けず、publish も service 呼び出しも行わない。
キー入力から Joy を作る画面は
[ps3_joy_sim 設計書](ps3_joy_sim_設計書.md)の対象である。

単体で GUI を起動する場合、RTK 状態の入力名を実機の完全名（`/rtk_gps/rtk_status`）へ
合わせる必要がある。

## 4. 設定の所在

一覧と既定値は [README](../README.md) と
[params/default.yaml](../params/default.yaml) を正とする。本章はどの設定がどの判定に効くか
と、特殊な値の扱いを定める。閾値の値と理由は 7 章に置く。

### 4.1 負のインデックスの扱い

ボタン・軸のインデックスに負の値を与えた場合の扱いが**項目によって異なる**。

| パラメータ | 負の値の扱い |
| --- | --- |
| `enable_button`（デッドマン） | **常に押されているものとして扱う。デッドマンが無効になる** |
| `l1_button_index` | 同上。L1 が常に押された状態になる |
| `ps_button_index` | 同上。PS が常に押された状態になる |
| `turbo_button` | 倍率の適用を行わない（無効化） |
| `linear_y_axis` | 横速度を 0 に固定（無効化） |

**デッドマンとモード遷移のボタンに負の値を設定すると、意図せず手動指令が常に有効に
なる。** 無効化の意図で負の値を与える運用はしない。インデックスが配列長を超える場合は
「押されていない」として扱い、理由文字列で通知する。

### 4.2 コントローラの番号割り当て

| 設定 | L1 | PS |
| --- | --- | --- |
| 単体起動の既定、Joy simulator | 4 | 16 |
| 共通実機起動（SDL 経由） | 4 | 10 |

PS ボタンの番号は Joy ドライバの設定で変わる。実機構成の値は
[実機ハードウェア統合](../../icart_bringup/docs/実機ハードウェア統合.md)を参照する。

`turbo_button` は既定で無効である。R1（インデックス 5）は融合ノードへの GNSS 途絶
模擬に使っており、倍率には割り当てない。

### 4.3 挙動に影響しないパラメータ

| パラメータ | 状況 |
| --- | --- |
| `manual_transition_trigger` | `l1_ps_button_hold` 以外を与えると warn を出し、同じ扱いにする。実装は 1 種のみ |
| `turn_preview_seconds` | GUI が受け取るが、表示文の生成では破棄する |
| `max_autonomous_resume_linear_x` | 同上 |
| `max_autonomous_resume_angular_z` | 同上 |

復帰予定方向の警告は、速度の大きさではなく**画面上の矢印角度**の閾値で決まる（7.5 節）。
上の 3 つのパラメータは閾値として使われていない。

### 4.4 入力倍率と車体の能力

`linear_scale` と `angular_scale` は、**Joy の軸の値を速度指令へ変換する倍率であり、
車輪の実効上限ではない。** 実際の上限と加減速度は `ypspur_ros2` が制限する。走行系全体の
値は
[走行システムの機能と制約](../../../docs/走行システムの機能と制約.md)を参照する。

既定の倍率・不感帯は、`manual_teleop_node`、`drive_status_gui_node`、`ps3_joy_sim_node`
の 3 箇所に同じ値を持つ。1 箇所だけ変更すると表示と実際の指令がずれる（9.1 節の試験が
照合する）。

## 5. データモデル・内部状態

### 5.1 モードと出力元

モードは 2 値、出力元は 3 値で、独立に保持する。

| 区分 | 値 |
| --- | --- |
| モード | `AUTONOMOUS`、`MANUAL` |
| 出力元 | `ZERO`、`AUTONOMOUS_CMD`、`MANUAL_CMD` |

### 5.2 mux が保持する状態

| 状態 | 初期値 | 更新契機 | クリア条件 |
| --- | --- | --- | --- |
| モード | `initial_mode` による | 遷移条件の成立 | なし |
| 手動遷移の長押し開始時刻 | なし | L1 と PS の同時押しが成立 | 条件が崩れる、手動へ遷移、手動モード中 |
| L1 解放の開始時刻 | なし | 手動モードで L1 が離れる | L1 再押下、自律へ遷移、手動固定時 |
| 自律復帰待ちの期限 | なし | 手動から自律への遷移 | 期限到達、手動へ遷移、手動モード中 |
| 最新 Joy（ボタンと受信時刻） | なし | Joy 受信 | なし |
| 最新の自律指令・手動指令 | なし | 各指令の受信 | なし |

**古い入力を破棄しない。** 鮮度は毎周期に時刻差で判定するため、保持値は残り続ける。

### 5.3 teleop が保持する状態

最新の Joy 入力（軸・ボタン・受信時刻）1 件のみである。他に状態を持たない。

## 6. 処理フローと異常時の挙動

### 6.1 周期処理

両ノードとも `publish_rate_hz` のタイマーで動く。購読コールバックは最新値を保存する
だけで、判断は行わない。

### 6.2 モード遷移

| 現モード | 条件 | 結果 |
| --- | --- | --- |
| `AUTONOMOUS` | Joy が新鮮かつ L1 と PS が同時に押された状態が `manual_transition_hold_s` 継続 | `MANUAL` へ遷移 |
| `AUTONOMOUS` | 上記の条件が途中で崩れる | 長押しの計測をやり直す |
| `MANUAL` | `allow_auto_resume` が false | 遷移しない（手動固定） |
| `MANUAL` | L1 を押している | 解放の計測をやり直す |
| `MANUAL` | L1 を離して `manual_to_auto_l1_released_s` 経過し、かつ自律指令が新鮮 | `AUTONOMOUS` へ遷移し、復帰待ちの期限を設定 |
| `MANUAL` | L1 を離して所定時間経過したが自律指令が古い | 遷移しない |

**L1 だけでは自律から手動へ切り替わらない。** PS との同時押しを要求する。誤操作による
モード変更を防ぐためである。

**Joy が途絶している間は手動へ遷移できない。** 自律モードのまま残る。

### 6.3 出力の決定

モード遷移の判定後、同じ周期で出力を決める。

自律モードの場合:

| 条件 | 出力元 | 出力値 |
| --- | --- | --- |
| 復帰待ちの残り時間が正 | `ZERO` | ゼロ |
| 自律指令が新鮮 | `AUTONOMOUS_CMD` | 自律指令そのまま |
| 自律指令が古い、または未受信 | `ZERO` | ゼロ |

手動モードの場合:

| 条件 | 出力元 | 出力値 |
| --- | --- | --- |
| L1 を押していない | `ZERO` | ゼロ |
| L1 を押しており手動指令が新鮮 | `MANUAL_CMD` | 手動指令そのまま |
| L1 を押しているが手動指令が古い | `ZERO` | ゼロ |

**自律モードでも出力がゼロになる状態が 2 つある。** 復帰待ちと自律指令の失効である。
モードの表示だけでは車体が動くかどうかは判定できない。

**手動モードでは L1 がデッドマンとして働く。** 離した時点で出力はゼロになる。モードは
手動のまま残る。

手動固定（`allow_auto_resume` が false）の場合、L1 を離しても手動モードを保ち、出力は
ゼロになる。L1 を押し直せば手動指令が再び有効になる。**経路採取の共通起動がこの設定を
使う。** 採取中に自律指令が流れていても、自律へ戻らないようにするためである。

### 6.4 手動速度指令の生成

1. Joy が未受信、または受信から期限を超えていればゼロ。
2. デッドマンのインデックスが配列長を超えていればゼロ。
3. デッドマンが押されていなければゼロ。
4. 前後軸・旋回軸・（有効なら）横軸を読む。各軸は不感帯と倍率を適用する。
5. その場旋回の不感帯を適用する（7.2 節）。
6. 軸の反転設定を適用する。
7. 倍率ボタンが有効かつ押されていれば倍率を全成分へ掛ける。
8. いずれかの成分が非有限ならゼロ。

**軸の反転は、その場旋回の不感帯を適用した後に行う。** 不感帯の判定は反転前の値に対して
行われる。対称な不感帯であるため結果は変わらない。

### 6.5 異常時の挙動

| 事象 | 挙動 |
| --- | --- |
| Joy 未受信・期限超過 | 手動指令をゼロ。モード遷移を行わない。理由を通知 |
| ボタンのインデックスが配列長を超える | 押されていないものとして扱い、理由を通知 |
| 軸のインデックスが配列長を超える | その軸を 0 として扱う |
| 軸に非有限値 | 指令全体をゼロ。理由を通知 |
| 自律・手動指令に非有限値 | その指令を無効として扱い、出力はゼロ（7.1 節） |
| `manual_transition_trigger` が未実装の値 | 起動時に warn を出し、実装済みの方式で動く |

### 6.6 終了処理

mux は終了時にゼロの `Twist` を 1 回配信する（3.2 節）。teleop と GUI は終了時に何も
配信しない。

`SIGINT` を終了処理中に再度受けても例外を外へ出さない。`destroy_node` と `shutdown` を
それぞれ `KeyboardInterrupt` で囲む。終了途中の割り込みでスタックトレースを出さない
ためである。

### 6.7 ログと理由の通知

理由は状態通知の文字列フィールドとして常に外部へ出す。`ZERO` を出した原因は
`autonomous_cmd_timeout`、`manual_cmd_timeout`、`manual_l1_released`、
`auto_resume_countdown`、`joy_timeout`、`joy_not_received`、`manual_locked`、
`joy_button_index_out_of_range` で区別する。

ログの出力は少ない。モードが変わった時のみ `info`、理由が変わった時に `debug` を出す。
起動時のパラメータ検査で `warn` を使う。**`error` と `fatal` は使わない。** 異常の通知は
ログではなく状態通知のフィールドで行う。

## 7. 判定ロジックと閾値

### 7.1 鮮度と有効性の判定

速度指令が「新鮮」とは、次の両方を満たすことである。

- 受信からの経過時間が期限以内
- `linear.x`、`linear.y`、`angular.z` のすべてが有限

期限の既定値は次のとおりである。

| 対象 | 既定値 | 理由 |
| --- | --- | --- |
| Joy（`joy_timeout_s`） | 0.5 秒 | — |
| 自律指令（`autonomous_cmd_timeout_s`） | 0.5 秒 | — |
| 手動指令（`manual_cmd_timeout_s`） | 0.3 秒 | **自律より短い。** 操縦中の指令が途絶した場合により早くゼロへ落とすため |

**非有限値を含む指令は、受信直後でも古い指令として扱う。** 出力はゼロになる。

「手動入力あり」は鮮度とは別の判定で、いずれかの成分の絶対値が 1e-6 を超えることを
意味する。状態通知に含めるが、出力の決定には使わない。**新鮮なゼロ指令と、指令の途絶は
区別して通知される。**

### 7.2 その場旋回の不感帯

旋回入力が 0 でない場合、前後軸の値が `linear_scale × in_place_turn_deadzone`
（既定 1.2 × 0.12 = 0.144 m/s）以下であれば前後速度を 0 にする。

横へスティックを倒すときに混ざる小さな前後入力を中立として扱い、左右の車輪を逆回転
させる旋回を成立させるためである。**判定は倍率を掛けた後の値に対して行う。** 比較の
基準も倍率を掛けた値であるため、倍率を変えても不感帯の比率は変わらない。

通常の不感帯 `deadzone`（既定 0.05）は倍率を掛ける前の軸の値に対して適用する。直進時の
微速操作を残すためである。大きな前後入力を伴う旋回（弧を描く走行）は維持される。

### 7.3 モード遷移の時間条件

| 条件 | 既定値 | 理由 |
| --- | --- | --- |
| 手動遷移の長押し（`manual_transition_hold_s`） | 2.0 秒 | 誤操作によるモード変更を防ぐ |
| L1 解放から自律復帰判定まで（`manual_to_auto_l1_released_s`） | 1.0 秒 | 一時的な持ち替えで復帰しないようにする |
| 自律復帰後のゼロ出力（`auto_resume_delay_s`） | 5.0 秒 | 7.4 節 |

手動遷移の長押し中、開始時刻からの経過秒を状態通知に入れる。長押しが成立していない
場合は 0.0 である。GUI が進捗の表示に使う。

### 7.4 復帰待ちの残り時間

手動から自律へ遷移した時点で `auto_resume_delay_s` 後を期限とし、毎周期に残り時間を
求める。残りが正の間は出力をゼロにする。期限に達した周期で期限を破棄する。

**復帰待ち中に自律指令が古くなった場合、残り時間は進み続けるが理由の通知が
`autonomous_cmd_stale` に変わる。** 期限到達後も自律指令が古ければ出力はゼロのままで
ある。

### 7.5 表示用の逆算

GUI は最終指令と復帰予定の自律指令から、スティック位置と矢印の方向を逆算する。

1. 速度を倍率で割ってスティック値へ戻す。
2. 反転設定を適用する。
3. 不感帯より小さい値を 0 にする。
4. 2 軸のノルムが 1 を超える場合は 1 へ正規化する（円内へ収める）。

矢印の角度から表示文を決める。

| 角度の絶対値 | 表示 |
| --- | --- |
| 15 度以下 | 前進 |
| 15 度超〜45 度未満 | 右旋回 / 左旋回 |
| 45 度以上〜90 度以下 | 右旋回 / 左旋回 + 急旋回注意 |
| 90 度超 | 後進 + 後方注意 |

**GUI の旋回軸は既定で反転させる**（`direction_angular_axis_invert` が true）。画面上で
右へ倒した表示が正の角速度に対応しないためである。`manual_teleop_node` 側の
`angular_axis_invert` は false であり、**2 つの設定は一致しない。** GUI は表示の向きを
合わせる目的で独立に持つ。

## 8. 並行性・周期・起動・依存関係

### 8.1 周期

| 項目 | 値 |
| --- | --- |
| teleop の指令配信 | `publish_rate_hz`（既定 20 Hz） |
| mux の指令・状態配信 | `publish_rate_hz`（既定 20 Hz） |
| 各入力の期限 | 7.1 節 |

### 8.2 並行性

callback group を指定しないため、既定の group で単一スレッドの executor が直列に処理
する。ロックを持たない。

GUI は PyQt5 の mainloop と ROS の spin を同一プロセスで動かす。表示モデルの生成を
`gui_core.py` へ分けており、Qt を初期化せずに単体試験できる。

### 8.3 起動

entry point は 4 ノード分である。launch の引数は [README](../README.md) を正とする。

`drive_mode_manager.launch.py` は `joy_input` で Joy の配信元を選ぶ。

| 値 | 起動するノード |
| --- | --- |
| `joy_node`（既定） | `joy` パッケージの `joy_node` |
| `ps3_joy_sim` | `ps3_joy_sim_node` |
| 上記以外 | どちらも起動しない（外部から `/joy` を配信する前提） |

**Joy の配信元は 1 つに限る。** 複数が同時に配信すると、ボタン状態が交互に入れ替わり
モード遷移が成立しない。

`start_gui` が false の場合は GUI を起動しない。GUI は表示専用であり、走行には不要で
ある。

mux は起動時に「`/cmd_vel` は本ノードが管理する」旨を info で出す。最終指令の配信元が
1 つであることを起動ログで確認できるようにするためである。

mux は `DiagnosticReporter` へ生存報告を登録する。teleop と GUI は登録しない。

### 8.4 依存関係

`ament_python` でビルドする。ビルド時の依存は `rclpy` と `tc_diagnostics` のみで、
`geometry_msgs`、`sensor_msgs`、`std_msgs`、`builtin_interfaces`、`tc_route_msgs`、
`rtk_gps_um982_msgs`、`joy`（実コントローラ入力）、`python3-pyqt5`（GUI）は実行時依存と
して宣言する。

pip で追加導入する固有の Python パッケージはない。

`*_core.py` の 4 モジュールは標準ライブラリのみで動く。Qt も ROS も要らない。

- **ソフトウェアの状態遷移が物理的な非常停止の代替になるかを検証していない。** 代替に

- Joy の `header.stamp` が古いメッセージを受けた場合の挙動を確認していない（3.5 節）。
- 負のインデックスを設定した場合の挙動（4.1 節）を実機で確認していない。コードから

## 10. 影響範囲・未決事項

### 10.1 影響範囲

`tc_route_msgs/DriveModeStatus` のフィールドを変更する場合、mux の配信処理と GUI の
表示モデル、`robot_console` の表示を併せて更新する。

`/cmd_vel` の消費者は `ypspur_ros2` である。**mux が最終指令の唯一の配信元である前提は
起動構成に依存する。** 他のノードが `/cmd_vel` へ配信する構成を作らない。

既定の倍率・不感帯は 3 箇所に同じ値を持つ（4.4 節）。1 箇所だけ変更すると表示と実際の
指令がずれる。

`allow_auto_resume` は共通採取起動が false を指定する。既定を変えると採取中に自律へ
復帰し得る。

### 10.2 未決事項

| 件 | 選択肢 | blocker |
| --- | --- | --- |
| 4.1 節: 負のインデックスがデッドマンを無効化する | 負の値を拒否する／「無効」の意味を項目間で揃える | ではない。無効化の意図で設定するとデッドマンが働かなくなる |
| 4.3 節: GUI の警告閾値パラメータ 3 個が使われていない | 速度の大きさで警告する機能を実装する／パラメータを削る | ではない |

| 3.5 節: Joy の時刻を受信時刻で判定している | `header.stamp` を使う判定へ変える（Joy ドライバ側の stamp の信頼性を確認した上で） | ではない |
