# robot_navigator 詳細設計書

## 1. 目的・スコープ

本書は `robot_navigator` パッケージの内部設計を定める。対象ノードは速度指令生成の
`robot_navigator` と、試験用の `robot_simulator` である。

トピック名、型、パラメータの一覧と起動方法は [README](../README.md) を正とする。
本書はそれを再掲せず、**制御則、制動距離の式、入力監視と封鎖停止の条件、能力照合の規則、
境界挙動と制約**を定める。

`/active_target` の目標姿勢へ車体を誘導する速度指令を生成する。入力は自己位置、車輪速度、
障害物距離であり、出力は `Twist` である。`route_follower` が `/active_target` を生成し、
本ノードが速度指令へ変換する。共通起動では融合による減速と `drive_mode_manager` の mux を
経て車輪ドライバへ渡る。

責務は次の 4 点である。

- 目標への角度誤差から角速度を算出する。
- 目標距離と障害物距離に対して停止できる線速度へ制限する。
- 入力の途絶を検出してゼロ速度を出力する。
- ドライバの実効能力が要求を満たすことを確認する。

非スコープは、経路の生成と追従点の管理（`route_follower` が担う）、障害物の観測
（`obstacle_monitor` が担う）、速度・加速度の物理的な制限（`ypspur_ros2` が担う）、
手動操縦である。

記載内容はすべて実装済みである。実路面・荷重での制動は実測していない（9.3 節）。

## 3. 外部インタフェース仕様

一覧は [README](../README.md) を正とする。本章は一覧に現れない取り扱いと、QoS の選定
理由を定める。

### 3.1 QoS

| 対象 | 設定 | 選定理由 |
| --- | --- | --- |
| `/cmd_vel`（配信） | RELIABLE / KEEP_LAST | 速度指令を取りこぼさないため |
| `/direction_marker`（配信） | RELIABLE / KEEP_LAST | 可視化のみ |
| `active_route`（購読） | RELIABLE / TRANSIENT_LOCAL / depth 1 | 起動順に依らず経路世代を受けるため |
| `obstacle_avoidance_hint`（購読） | **BEST_EFFORT** | **配信元が BEST_EFFORT のため、RELIABLE では QoS 非互換で購読が成立しない** |
| `/scan`（購読） | `qos_profile_sensor_data` | センサ入力の標準プロファイル |
| `/motion_limits`（購読） | 既定 / depth 1 | — |
| その他の購読 | 既定 / depth 10 | — |

### 3.2 `/cmd_vel`（配信）

`linear.x` と `angular.z` のみを設定する。**横速度は出さない。**

制御周期ごとに配信する。入力途絶・封鎖停止・入力未揃いのいずれでもゼロの `Twist` を
配信するため、**配信が止まるのはノードが停止した場合のみ**である。

**終了時に安全値を配信しない。** 最後の値が下流に残る。

### 3.3 `/active_target`（購読）

目標姿勢として使う。受信するたびに**目標の世代番号を進め、位置・角度の到達フラグを
解除する**（7.2 節）。

**受信期限を監視しない。** 目標の再送が止まっても、保持している目標への指令を出し続ける。
`route_follower` の待機・完了状態も購読しないため、**follower 停止時の指令失効は保証
しない**（10.1 節）。

### 3.4 `/obstacle_avoidance_hint` と `/scan`（購読）

`obstacle_distance_mode` で入力を選ぶ。`hint`（既定）は
`ObstacleAvoidanceHint.front_clearance_m`、`scan` は前方帯の距離を使う。選んだ側のみを
購読する。

**非有限な hint 距離は「距離なし」へ変換し、距離制約を適用しない**（7.4 節）。
`obstacle_monitor` が点数不足時に inf を返すためである。

### 3.5 `/motion_limits`（購読）

`require_motion_limits`（既定 true）が有効なとき購読し、ドライバの実効能力と自ノードの
要求値を照合する（7.5 節）。

**この入力は監視対象に含まれる。** 不整合または古い場合、受信記録を破棄して入力途絶と
同じ扱いにし、ゼロ速度を出力する。

### 3.6 画面・可視化

`/direction_marker` に ARROW Marker を配信する。現在位置を始点とし、算出した角速度を
加味した向きへ伸ばす。長さは線速度に応じて 0.3〜2.0 m の範囲で変える。frame は
`marker_frame`（既定 `map`）とする。

RViz での進行方向の確認に使う表示専用の経路であり、制御には影響しない。本パッケージは
GUI を持たない。

## 4. 設定の所在

一覧と既定値は [README](../README.md) と
[params/default.yaml](../params/default.yaml) を正とする。本章はどの設定がどの判定に効くか
と、変更できない範囲を定める。閾値の値と理由は 7 章に置く。

### 4.1 起動後に変更できないパラメータ

次の 7 個は**読み取り専用として宣言する。** 実行中に変更できない。

| パラメータ | 効く判定 |
| --- | --- |
| `max_vel`、`max_w` | 速度・角速度の上限（7.1 節）、能力照合（7.5 節） |
| `max_acc_v` | 線速度の上昇側の加速度制限（7.1 節） |
| `max_acc_w` | **能力照合にのみ使う**（7.5 節）。角指令の変化率は制限しない |
| `max_decel_v` | 制動距離の計算（7.3 節）、能力照合 |
| `braking_delay_sec` | 制動距離の計算（7.3 節） |
| `require_motion_limits` | 能力照合を行うか（7.5 節） |

走行中に能力の前提が変わらないようにするためである。

### 4.2 変更できるパラメータ

| パラメータ | 効く判定 |
| --- | --- |
| `pos_tol`、`pos_tol_exit_margin`、`ang_tol` | 到達判定（7.2 節） |
| `control_rate_hz` | 制御周期（8.1 節） |
| `pose_timeout_sec`、`odom_timeout_sec`、`obstacle_timeout_sec` | 入力監視（7.6 節） |
| `road_block_hold_sec` | 封鎖停止の保持時間（7.7 節） |
| `min_obstacle_distance` | 障害物までの余裕（7.4 節） |
| `obstacle_distance_mode` | 障害物距離の入力（3.4 節） |
| `robot_width`、`safety_distance`、`obst_max_dist` | `scan` モードの前方帯の抽出 |
| `marker_frame` | 可視化の frame |
| `log_csv_path` | CSV ログの出力先 |

### 4.3 ROS から設定できない値

角速度 PID のゲインと積分の上限は実装内の固定値であり、パラメータを持たない。値は
7.1 節に置く。

## 5. データモデル・内部状態

| 状態 | 初期値 | 更新契機 | クリア条件 |
| --- | --- | --- | --- |
| 現在姿勢 | なし | `/localization/pose_enu` 受信 | なし |
| 現在速度 | なし | odom 受信 | なし |
| 現在目標 | なし | `/active_target` 受信 | なし |
| 目標の世代番号 | 0 | `/active_target` 受信ごとに +1 | なし |
| 障害物距離 | なし | hint または scan の受信 | 非有限値を受けると「なし」へ |
| 前回の指令 | ゼロ | 指令の配信ごと | 入力途絶でゼロへ |
| PID の積分項 | 0.0 | 制御周期ごと | 入力途絶、到達、誤差符号の反転でリセット |
| 直前の角度誤差 | 0.0 | 制御周期ごと | 入力途絶でリセット |
| 位置許容内フラグ | false | 位置許容内へ入った周期 | **新しい目標の受信のみ** |
| 角度許容内フラグ | false | 位置許容内かつ角度許容内へ入った周期 | 同上 |
| 封鎖停止の状態一式 | 非活性 | `/road_blocked` 受信 | 解除条件の成立（7.7 節） |
| 経路世代 | なし | `active_route` 受信 | なし |
| 途絶中の入力名 | 空 | 制御周期ごと | — |

**到達フラグはヒステリシスを持つ。** 一度位置許容内へ入ると、距離が離れても解除せず、
新しい目標を受信するまで保持する。目標位置を通過した際に進行方向を維持したまま離脱する
ことを防ぐためである。

**入力の鮮度は受信時刻で判定する。** 自己位置・odom・障害物・運動能力の各入力は、
メッセージの stamp ではなく受信した時刻を記録する。例外は運動能力で、stamp の古さも
併せて検査する（7.5 節）。

## 6. 処理フローと異常時の挙動

### 6.1 制御ループ

`control_rate_hz` のタイマーで次を実行する。

1. 入力監視で途絶している入力を調べる。**1 つでもあれば、PID の積分・直前誤差・前回
   指令をクリアしてゼロ速度を配信し、以降の処理を行わない**（7.6 節）。
2. 封鎖停止の継続が必要かを判定する。必要ならゼロ速度を配信して終了する（7.7 節）。
3. 姿勢・速度・目標のいずれかが未受信なら、ゼロ速度を配信して終了する。
4. 制御則で指令を算出する（7.1〜7.4 節）。
5. 指令を配信し、前回指令として保持する。
6. 進行方向の Marker を配信する。
7. CSV ログが有効なら 1 行追記して flush する。

別に 1 秒周期で目標の状態をログへ出すタイマーを持つ。

### 6.2 異常時の挙動

| 入力・事象 | 正常時 | 異常時 |
| --- | --- | --- |
| 自己位置、odom | 制御に使う | 未受信・期限超過で**ゼロ速度**。初回の遷移時に warn、復帰時に info |
| 障害物距離 | 線速度を制限 | 期限を監視する設定なら途絶でゼロ速度。非有限値は距離制約なしへ（7.4 節） |
| 運動能力 | 走行を許可 | 不整合・古いと error（2 秒間引き）を出し、**受信記録を破棄してゼロ速度** |
| 目標 | 制御に使う | 未受信ならゼロ速度。warn を 5 秒間引きで出す。**受信期限は監視しない** |
| `/road_blocked` | — | true で封鎖停止へ入る（7.7 節）。停止中は warn を 1 秒間引きで出す |
| 設定値が非有限・非正 | — | **起動時に例外を投げてノードを起動しない**（7.8 節） |
| CSV の書き出し | 1 行追記 | ファイルを開けない場合はログを無効化して制御を続ける |

### 6.3 終了処理

ノードを破棄して ROS をシャットダウンする。CSV を閉じる。**終了時に安全値を配信
しない**（3.2 節）。

### 6.4 ログ

| 重要度 | 用途 |
| --- | --- |
| `info` | 起動、入力の復帰、封鎖停止の解除、1 秒周期の目標状態 |
| `warn` | 入力の途絶（初回）、入力未揃い（5 秒間引き）、封鎖停止中（1 秒間引き） |
| `error` | 運動能力の不整合（2 秒間引き） |

`debug` と `fatal` は使わない。間引きは `throttle_duration_sec` で行う。

`DiagnosticReporter` へ生存報告を登録する。監視側の扱いは
[ノード健全性監視設計](../../../docs/ノード健全性監視設計.md)を参照する。

## 7. 判定ロジックと閾値

### 7.1 角速度と線速度の算出

角速度は角度誤差の PID で求める。ゲインは実装内の固定値である。

| 項目 | 値 |
| --- | --- |
| 比例ゲイン | 0.65 |
| 積分ゲイン | 0.001 |
| 微分ゲイン | 0.02 |
| 積分の上限 | `max_w` ÷ 積分ゲイン |

積分は次の規則で扱う。

- **誤差の符号が反転した周期で積分をリセットする。** 飽和からの回復を早めるためである。
- 角速度が上限で飽和している間は、**誤差が逆方向のときのみ積分を更新する。** 同方向の
  誤差では積分を増やさない（アンチワインドアップ）。

角度誤差の基準は到達状況で切り替える。

| 状況 | 誤差の基準 |
| --- | --- |
| 位置許容内へ入る前 | **目標位置へのベアリング** |
| 位置許容内へ入った後 | 目標姿勢の yaw |

位置到達前に目標姿勢の yaw を使うと、目標を通過した際に進行方向を維持したまま離脱する
ためである。

線速度は次の順に決める。

1. 目標距離が正かつ位置許容内でなければ、前回の実測速度に `max_acc_v × 制御周期` を
   加えた値と `max_vel` の小さい方を基準速度とする。位置許容内なら 0 とする。
   **上昇側のみを制限し、減少側は制限しない。**
2. 角度誤差に応じたスケール `max(0, 1 − 角度誤差 / π)` を掛ける。
3. 目標距離に対する制動制限を適用する（7.3 節）。
4. 障害物距離があれば、そこから `min_obstacle_distance` を引いた距離に対する制動制限を
   適用する。
5. 0 と `max_vel` の範囲へ丸める。

### 7.2 到達判定

| 判定 | 条件 |
| --- | --- |
| 位置許容内 | 目標距離が `pos_tol`（既定 0.5 m）以下 |
| 角度許容内 | 位置許容内かつ角度誤差が `ang_tol`（既定 0.25 rad）以下 |
| 到達 | 位置許容内かつ角度誤差が `ang_tol` 以下 |

到達すると線速度と角速度をゼロにし、積分をリセットする。

**角度許容内フラグが立った後は角速度をゼロに固定する。** 位置許容外での障害物停止など、
他の停止には影響しない。

`pos_tol_exit_margin`（既定 0.2）は離脱判定の余裕として宣言するが、**到達フラグの解除は
新しい目標の受信のみで行う**（5 章）ため、現在の制御では参照されない。

### 7.3 制動距離と速度制限

制動距離は一定減速度を仮定し、応答遅れ中の走行を加えて求める。

```
制動距離 = |速度| × 遅延 + 速度² / (2 × 減速度)
遅延     = braking_delay_sec + 制御周期
```

逆関数で、与えられた距離に対して停止できる速度を求める。ゼロ近傍で数値的に安定な形
（分母に平方根と遅延項の和を置く形）を使う。

**使う速度は、実測速度と直前指令の絶対値の大きい方とする。** 旋回で角度スケールにより
指令が縮んでいても、実際の運動量を過小評価しないためである。

いずれかの値が非有限なら 0 を返す。制動距離が距離以上であれば 0 を返す。そうでなければ
提案速度と制限速度の小さい方を採る。

既定値（`max_decel_v` 1.5 m/s²、`braking_delay_sec` 0.2 s、制御周期 0.05 s）では、
1 m/s に対して制動約 0.333 m と遅延 0.25 m になる。これに障害物余裕 0.5 m を加えた
約 1.083 m が基準となる。**一定減速度を仮定した設計モデルであり、実路面・荷重での停止
距離の実測値ではない。**

**制動は線速度にのみ適用する。** 障害物による線速度の停止中、角度誤差が `ang_tol` 以下
であれば角速度もゼロにするが、**それを超える角度誤差があれば旋回指令は残る。**

### 7.4 障害物距離の扱い

`hint` モードでは `front_clearance_m` を使う。**非有限値（inf、NaN）は「距離なし」へ
変換し、距離制約を適用しない。**

したがって、**新鮮なメッセージを受け取っていても有効な障害物観測が成立しているとは
限らない。** `obstacle_monitor` は点数不足時に inf を返す（
[obstacle_monitor 詳細設計書](../../obstacle_monitor/docs/obstacle_monitor_詳細設計書.md)
7.5 節）。

`obstacle_timeout_sec` は単体の既定が 0 で監視無効、共通実機起動は 1 秒で監視する。
**0 のときは障害物入力が途絶しても停止しない。**

### 7.5 ドライバ能力の照合

`require_motion_limits` が有効なとき、`/motion_limits` を受けて次を検査する。

1. 5 項目（最大線速度、最大角速度、線加速度、角加速度、線減速度）について、**自ノードの
   要求値がドライバの実効値以下**であることを確認する。等値を許す（許容 1e-9）。
2. メッセージの stamp の古さが 0 以上 0.5 秒未満であることを確認する。

両方を満たせば受信を記録して走行を許可する。満たさなければ**受信記録を破棄し、入力途絶
として扱う。** 監視の期限は 0.5 秒で固定であり、パラメータを持たない。

**照合はドライバの能力が要求値以上であることの確認であり、等値である必要はない。**
`max_acc_w`（既定 0.6）はドライバ能力への要求値であり、**本ノード内で角指令の変化率を
制限する値ではない。** ドライバは 1.5 rad/s² を配信するため、この要求を満たす。

`/motion_limits` を配信しない構成（Gazebo など）では `require_motion_limits` を false に
して監視を無効化する。

### 7.6 入力途絶の判定

入力ごとに最終受信時刻を保持し、次のいずれかで途絶とする。

- 一度も受信していない
- 経過時間が期限以上
- **経過時間が負（時計の逆行）**
- 現在時刻が非有限

判定時刻は実機で単調時計、`use_sim_time` が真のときは ROS 時計とする。**低速な物理計算や
一時停止の wall 時間を模擬入力の欠測に数えない**ようにするためである。

監視対象は自己位置と odom、`obstacle_timeout_sec` が正なら障害物、
`require_motion_limits` が有効なら運動能力である。**期限はそれぞれ独立で、どれか 1 つが
途絶すればゼロ速度になる。** 復帰にはすべての入力が新鮮である必要がある。

**ROS メッセージ自体の stamp の鮮度は、この監視では検証しない**（運動能力を除く）。
古い内容の再配信、LiDAR の途絶、自己位置の品質低下、ノード自体の停止は別途対策が要る。

### 7.7 封鎖停止

`/road_blocked` が true になると封鎖停止へ入り、`road_block_hold_sec`（既定 5.0 秒）の
期限を設定する。停止中はゼロ速度を配信する。

解除は次の順で判定する。

1. 期限内であれば停止を継続する。
2. 期限を過ぎても、**`/active_target` の内容が更新されていなければ停止を継続する。**
   更新の判定には目標の世代番号・stamp・経路世代を使う。
3. 更新が確認できれば封鎖状態を解除し、制御を再開する。

**`active_route` の更新の有無にかかわらず、`/active_target` の内容更新を必須条件とする。**
封鎖された経路へそのまま復帰しないためである。停止中は待機理由（タイマ満了待ち、
`active_target` 更新待ち、`active_route` 更新待ち）を warn へ出す。

### 7.8 設定値の起動時検査

運動能力と制御周期は有限かつ正であることを要求する。`braking_delay_sec` は有限かつ
非負であることを要求する。`obstacle_timeout_sec` は有限かつ非負であることを要求する。

**満たさない場合は起動時に例外を投げ、ノードを起動しない。** 不正な設定で走行指令を出す
ことを防ぐためである。

## 8. 並行性・周期・起動・依存関係

### 8.1 周期

| 項目 | 値 |
| --- | --- |
| 制御ループ（指令・Marker・CSV） | `control_rate_hz`（既定 20 Hz） |
| 目標状態のログ | 1.0 秒（固定） |
| 運動能力の監視期限 | 0.5 秒（固定、7.5 節） |
| その他の入力期限 | 4.2 節のパラメータ |

### 8.2 並行性

callback group を指定しないため、既定の group で単一スレッドの executor が直列に処理
する。ロックを持たない。購読コールバックは最新値と受信時刻を保存するだけで、制御の判断は
タイマー内で行う。

**CSV ログは毎周期 flush する。** 書き出しがコールバック内で同期的に行われるため、
低速なストレージでは制御周期に影響し得る。

### 8.3 起動

entry point は `robot_navigator` と `robot_simulator` である。launch の引数は
[README](../README.md) を正とする。

launch はトピック名を引数で remap できる。単体構成では `/cmd_vel`、統合構成では
`/cmd_vel/autonomous` へ出す。

起動時に設定値を検査する（7.8 節）。外部デバイスへの接続やファイル読み込みは行わない。
CSV ログの出力先は既定でホームディレクトリ配下とする。

### 8.4 同梱シミュレータ

`robot_simulator` は試験用に車体の運動を模擬し、odom と運動能力を配信する。契約の既定値は
最大線速度 2.0 m/s・角速度 3.0 rad/s、線加速度 0.7 m/s²・線減速度 1.5 m/s²・角加速度
1.5 rad/s² である。

**これらは契約として配信される値であり、シミュレータの速度更新に物理的な加減速を再現
するものではない。** 指令をそのまま速度として積分する。

### 8.5 依存関係

`ament_python` でビルドする。依存は `rclpy`、`tc_diagnostics`、`geometry_msgs`、
`nav_msgs`、`sensor_msgs`、`std_msgs`、`visualization_msgs`、`tc_route_msgs` である。

`braking.py` と `input_watchdog_core.py` は標準ライブラリのみで動く。`numpy` に依存
しない。

## 9. 確認方法と未確認範囲

### 9.1 自動確認

`tests/` の 5 ファイルが ROS 非依存で動く。車体もドライバも使わない。

| 試験 | 固定する内容 |
| --- | --- |
| `test_braking.py` | 遅延込みの制動距離と逆関数の整合、離散時間で障害物余裕を越えないこと、旋回による指令縮小と直前指令で運動量を隠せないこと、不正な減速度の拒否、**実機・シミュレータ・設計値の 3 層が一致すること** |
| `test_motion_contract.py` | 契約の不整合・古さ・欠落でゼロ速度になること、目標手前での制動と旋回時の運動量 |
| `test_input_watchdog_core.py` | 不正な期限で起動に失敗すること、未受信の境界と期限の独立性、復帰には両入力の鮮度が必要なこと、時計の逆行と非有限時刻で停止すること |
| `test_input_clock.py` | 模擬時計が wall 時間の遅れで失効しないこと、実時計では wall のタイムアウトを検出すること、途絶で停止して制御器がクリアされること、障害物欠落で停止すること |
| `test_simulator_motion_limits.py` | シミュレータの能力が制御側の要求を満たすこと、実ドライバと同じ契約を宣言すること、配信周期が監視を満たすこと |

**制動の試験は 3 箇所の値を照合する。** 設計値、`robot_simulator` の契約、実ドライバの
設定が片方だけ変更された場合に検出する。

### 9.2 手動で確認する範囲

- 単体構成での `/cmd_vel`、統合構成での `/cmd_vel/autonomous`・`/drive_mode_status`・
  最終 `/cmd_vel`・`/direction_marker` の挙動
- CSV ログの内容
- 目標手前での減速と停止位置
- 障害物による減速と、停止中に旋回指令が残る条件（7.3 節）
- 入力途絶（自己位置、odom、障害物、運動能力）それぞれでのゼロ速度と復帰
- 封鎖停止の保持と、`/active_target` 更新による解除（7.7 節）
- `require_motion_limits` を false にした構成での起動

### 9.3 未確認範囲

- **実路面・荷重での制動距離を実測していない。** 制動式は一定減速度を仮定した設計モデル
  である（7.3 節）。
- 実機走行での追従精度と、目標通過時の挙動を確認していない。
- PID ゲインが実車のタイヤ・路面に対して適切かを確認していない。固定値であり調整経路が
  ない（4.3 節）。
- 障害物停止中に旋回指令が残る条件（7.3 節）の安全性を実機で確認していない。
- CSV の毎周期 flush が制御周期へ与える影響を測定していない（8.2 節）。
- 目標の受信期限を監視しない点（3.3 節）の影響を実機で確認していない。

## 10. 影響範囲・未決事項

### 10.1 影響範囲

`tc_route_msgs` の `ObstacleAvoidanceHint`、`MotionLimits`、`Route` に依存する。
フィールドの変更は `obstacle_monitor`、`ypspur_ros2`、`route_manager` にも影響する。

`/cmd_vel` の消費者は `drive_mode_manager` の mux である。統合構成では
`/cmd_vel/autonomous` へ remap する。

**`route_follower` の待機・完了状態と実測速度ゼロは別である。** 目標再送が止まっても
本ノードが保持する目標は解除されない。本ノードは `/follower_state` を購読せず、
`/active_target` の受信期限も監視しないため、follower 停止時の指令失効は保証されない。
この制約は両パッケージにまたがるため
[走行システムの機能と制約](../../../docs/走行システムの機能と制約.md)に集約する。

能力の要求値（`max_vel`、`max_w`、`max_acc_v`、`max_acc_w`、`max_decel_v`）は
`ypspur_ros2` の実効設定と `robot_simulator` の契約の 3 箇所で対応する。1 箇所だけ変更
すると照合が失敗して走行できない（9.1 節の試験が照合する）。

### 10.2 未決事項

| 件 | 選択肢 | blocker |
| --- | --- | --- |
| 3.3 節: 目標の受信期限を監視しない | `/active_target` に期限を設ける／`/follower_state` を購読して停止状態を反映する | ではない。follower 停止時の指令失効が保証されない |
| 7.3 節: 障害物停止中に旋回指令が残る | 線速度ゼロ時に角速度もゼロにする／現状どおり角度誤差で判断する | ではない |
| 7.2 節: `pos_tol_exit_margin` が参照されない | 離脱判定を実装する／パラメータを削る | ではない |
| 4.3 節: PID ゲインが固定値である | パラメータへ出す／固定のまま文書で明示する（現状） | ではない。実車での調整経路がない |
| 7.4 節: `obstacle_timeout_sec` の既定が 0 である | 既定を正の値にする／共通起動で必ず指定する（現状） | ではない。単体では障害物途絶で停止しない |
