# route_planner 詳細設計書

## 1. 目的・スコープ

本書は `route_planner` パッケージの内部設計を定める。対象ノードは経路生成の
`route_planner` のみである。

パラメータ、CSV の列仕様、YAML のブロック定義、サービス一覧、起動方法は
[README](../README.md) を正とする。本書はそれを再掲せず、**経路の組み立て順序、
グラフ探索の定式化、姿勢の再計算範囲、封鎖再探索の構成、キャッシュと状態の寿命**を定める。

LLH と ENU の変換式および投影原点は
[geo_pose_converter 詳細設計書](../../geo_pose_converter/docs/geo_pose_converter_詳細設計書.md)が
正である。本パッケージはその変換を利用する側であり、式を持たない。

現地で採取した点列（CSV）と、交差点を節点とするグラフから走行経路を組み立てて
`route_manager` へ渡す。責務は次の 4 点である。

- YAML のブロック定義に従い、固定区間の点列と可変区間の探索結果を連結する。
- 必須通過点をすべて通る順序を決める。
- 区間の接続部と逆走区間の姿勢を再計算する。
- 封鎖が報告された区間を除いて再探索し、現在位置から接続する部分経路を返す。

非スコープは、走行速度・停止判断・サービス待機の管理（`route_manager` と
`route_follower` が担う）、LLH と ENU の変換式の定義（`geo_pose_converter` が担う）、
経路 CSV の採取（`route_survey` が担う）である。

記載内容はすべて実装済みである。生成した経路を実機で走行して確認した範囲は限られる
（9.3 節）。

## 2. 構成とファイル配置

| モジュール | 行数規模 | 責務 |
| --- | --- | --- |
| `route_planner.py` | 約 1,300 | ROS 層。サービス応答、ROS メッセージ変換、姿勢再計算、封鎖再探索の手順 |
| `route_builder.py` | 約 1,700 | ブロック定義の読み込み、CSV の解析、区間の連結、スライス、グラフの保持 |
| `graph_solver.py` | 約 900 | グラフ探索、通過順序の最適化、地図への重畳描画 |
| `latlon_to_pixel_mapper.py` | 約 350 | 緯度経度と地図画像の画素座標の対応 |

`route_builder.py` と `graph_solver.py` は ROS に依存せず、どちらも単体のスクリプトとして
実行できる `main()` を持つ。ROS メッセージ型を使わず、独自の `WaypointRecord` で経路を
扱う。ROS 層はこれを `tc_route_msgs/Waypoint` へ変換する。

| パス | 用途 |

| `routes/<環境名>/route_config*.yaml` | ブロック定義 |
| `routes/<環境名>/fixed/` | 固定区間の Waypoint CSV |

| `routes/<環境名>/variable/segments/` | エッジごとの Waypoint CSV |

`tools/` は経路データの整備に使う独立したスクリプト群である。ノードからは呼ばない。

| ツール | 用途 |

環境は `tsukuba`、`tsukuba2026_digital_twin`、`inagi`、`simulation`、
`obstacle_route_sim/<形状>_w<幅>` を持つ。`obstacle_route_sim` 配下は障害物回避の
シミュレーション用で、直線・クランク・S 字の 3 形状と通行幅 2 / 3 / 5 m の組み合わせである。

## 3. 外部インタフェース仕様

サービス定義は
[GetRoute.srv](../../tc_route_msgs/srv/GetRoute.srv)、
[UpdateRoute.srv](../../tc_route_msgs/srv/UpdateRoute.srv) を正とする。

### 3.1 QoS

**トピックの配信・購読を持たないため QoS 設定はない。** 2 つのサービスのみを提供する。

### 3.2 版番号

`/get_route` の成功で版を **1 に初期化**し、`/update_route` の成功ごとに +1 する。
失敗では変えない。

この版は `route_manager` が `major` として扱う値である。`route_manager` は `minor` を
別に持ち、公開値を `major * 100 + minor` で作る。**本ノードは `minor` を知らない。**
`/update_route` の要求に入る版は `major` だけである。

### 3.3 Route への付帯情報

応答する `Route` には次を設定する。

| フィールド | 値 |
| --- | --- |
| `header.frame_id`、`map_frame_id` | 投影設定の map フレーム名 |
| `earth_frame_id` | 投影設定の earth フレーム名 |
| `projection` | 投影原点（緯度・経度・高度）と投影の識別子 |
| `route_id` | `route_id` パラメータの値 |
| `route_image` | 可変区間の探索結果を地図へ重畳した PNG |

`projection` を入れるのは、各 waypoint の ENU 座標と LLH 座標がどの投影条件で対応するかを
受け取り側が判定できるようにするためである。**生成した経路の投影原点と、走行時の自己
位置推定の原点が一致している必要がある。** 一致の検査は本ノードでは行わない。

`route_image` は可変区間がある場合のみ地図へ重畳する。重畳に失敗した場合、および可変
区間がない場合は、文字列を描いた代替 PNG を返す。**`route_image` が常に有効な画像である
ことを前提にできる**が、内容が経路図である保証はない。`route_manager` は画像の有効性を
受理条件にしている（
[route_manager 詳細設計書](../../route_manager/docs/route_manager_詳細設計書.md)
3.2 節）ため、代替 PNG も受理される。

### 3.4 画面・可視化

ノード自体は GUI を持たない。`route_image` として地図への重畳図を応答に入れ、
`robot_console` が経路確認に表示する。

`tools/plot_edges_on_map.py` はエッジ CSV を地図へ重畳した PNG を
`routes/<環境名>/variable/` 配下へ出力する。経路データの整備時にオフラインで使う。

## 4. 設定の所在

一覧と既定値は [README](../README.md) を正とする。本章は解決の基準を定める。読み込み失敗時の
挙動は 6.5 節に置く。

| パラメータ | 解決の基準 |
| --- | --- |
| `config_yaml_path`、`csv_base_dir`、`map_image_path`、`map_worldfile_path` | 本パッケージの share ディレクトリ |
| `projection_config_path` | `geo_pose_converter` の share ディレクトリ |

`map_image_path` と `map_worldfile_path` は**両方が解決できた場合のみ**地図描画を有効に
する。片方だけ解決できた場合は警告を出して両方を無効化する。

ブロック定義は YAML ファイル、またはノードパラメータ
`route_planner.ros__parameters.blocks` のどちらでも同じ形式で与えられる。

**投影条件は本パッケージのパラメータではない。** `geo_pose_converter` の parameter YAML を
参照するだけで、原点を自分で持たない。**同梱の東京駅原点を実コースの原点として流用
しない。** 使用する経路の設定を指定する。

## 5. データモデル・内部状態

### 5.1 Waypoint の座標系

Waypoint CSV は **LLH 系と ENU 系のどちらか一方を正本**として持つ。判定と扱いは
次のとおりである。

| CSV の内容 | 扱い |
| --- | --- |
| 緯度・経度・方位が揃う | LLH 正本。ENU pose を変換で生成する |
| `x`,`y` のみ | ENU 正本。そのまま使う |
| 両方が有効 | **LLH を正本とし、警告を出す**。ENU 側は整合性の検査に使う |

両方が有効な場合の検査の閾値と帰結は 7.10 節に置く。

**走行用の ENU pose は 2 次元として扱い、`pose.position.z` を 0.0 に正規化する。**
LLH の高度は有効フラグで区別して保持し、走行判断には使わない。

### 5.2 保持する状態

| 状態 | 初期値 | 更新契機 | クリア条件 |
| --- | --- | --- | --- |
| ブロック定義 | 空 | 起動時の読み込み、経路生成 | なし |
| 区間キャッシュ（segment_id → 点列） | 空 | 起動時の読み込み | なし |
| グラフ（ブロックごと） | 空 | 起動時の読み込み、封鎖エッジの除去 | **なし** |
| 現在経路と由来情報 | なし | 経路生成の成功 | なし |
| 版番号 | 0 | 経路生成の成功 | なし |
| 要求時の通過点集合 | 空 | `/get_route` の成功 | なし |
| 通過済み通過点の履歴（ブロックごと） | 空 | `/update_route` の処理 | `/get_route` の成功 |

**CSV の読み込みとグラフの構築は起動時に 1 回だけ行う。** `/get_route` は再読み込みを
しない。したがって次の 2 点が帰結する。

- **CSV や YAML を変更した場合、ノードを再起動しなければ反映されない。** `colcon build`
  を `--symlink-install` で行っていても同様である。
- **封鎖として除去したエッジは、ノードを再起動するまで戻らない。** `/get_route` を
  呼び直してもグラフは復元されない。通過済み通過点の履歴のみがリセットされる。

### 5.3 由来情報

経路の各 waypoint に対し、同じ長さの由来情報の配列を保持する。

| 項目 | 用途 |
| --- | --- |
| ブロック名・ブロック番号 | ブロック境界の判定、封鎖対象ブロックの特定 |
| `segment_id` | 区間の切れ目の判定、仮想区間の識別 |
| エッジの両端点 | 封鎖エッジの特定と再探索の起点 |
| 区間内の局所 index | 仮想区間の生成時に、現在位置から起点へ戻る点列を切り出す位置 |
| CSV の向きと走行向きが一致するか | 逆走区間の判定、局所 index の読み替え |

由来情報は `/update_route` の処理に必須である。これが欠けている可変区間の waypoint は
異常として扱い、再探索を失敗させる。

## 6. 処理フローと異常時の挙動

### 6.1 起動

1. パラメータを解決し、投影設定を読み込む。
2. ブロック定義を読み込み、正規化する。
3. 固定ブロックの CSV と、可変ブロックのエッジごとの CSV を読み込んで区間キャッシュへ
   入れる。可変ブロックはグラフも構築する。
4. 読み込んだ点列を ROS メッセージ形式へ変換し、ROS 層側のキャッシュへ複製する。
5. `/get_route` と `/update_route` を登録する。

**読み込みの失敗は起動を止めない**（6.5 節）。

### 6.2 `/get_route`

1. ブロック定義を順に処理する。
   - 固定ブロック: 区間キャッシュの点列をそのまま使う。
   - 可変ブロック: グラフ探索（7.2 節）を行い、得られたエッジ列の区間 CSV を走行向きに
     合わせて連結する。CSV の向きと逆に辿る場合は点列を反転する。
2. 区間の連結時、接続点が同一座標なら重複を 1 点に畳む（7.3 節）。
3. `start_label` と `goal_label` が指定されていれば、その範囲へ切り出す（7.4 節）。
4. 姿勢を再計算する（7.5 節）。
5. 固定区間フラグを各 waypoint へ付ける。
6. index を 0 から振り直し、総距離を求める。
7. 可変区間があれば探索結果を地図へ重畳して PNG を作る。無ければ代替 PNG を作る。
8. 版を 1 にし、応答を組み立てる。現在経路と由来情報を保存し、通過点の履歴をリセットする。

### 6.3 `/update_route`

1. 現在経路を保持していなければ失敗。
2. 要求の版が現在経路の版と一致しなければ失敗。現在経路をそのまま応答へ入れる。
3. 次を検証する。いずれも満たさなければ失敗。
   - `prev_index` が `[0, 点数-2]` の範囲にある
   - `current_index` が `prev_index + 1` である
   - `prev_wp_label` と `current_wp_label` が現在経路の該当点のラベルと一致する
4. 両点の由来情報を見て、**同一ブロックに属すること**を確認する。
5. ブロックが固定なら、warn を出して失敗を返す（7.6 節）。
6. 走行中エッジの両端点（U と V）を由来情報から取り、グラフから両方向の辺を除去する。
   除去対象が見つからない場合は warn を出して処理を続ける。
7. 未通過の通過点集合を求める（7.7 節）。
8. 仮想区間（現在位置 → prev → U）の点列を作り、新経路の先頭に置く（7.8 節）。
9. ブロックの開始節点を U へ、通過点を未通過分へ一時的に差し替えて経路を組み立て直す。
   組み立て後に差し替えを元へ戻す。
10. 仮想区間と組み立て結果を連結し、姿勢を再計算して index を振り直す。
11. 版を +1 し、応答を組み立てる。現在経路と由来情報を更新する。

### 6.4 終了

サービスのみを持つため、終了時に配信する値はない。保持した経路は破棄される。
**`route_manager` 側は最後に受け取った経路を保持し続ける。**

### 6.5 異常時の挙動

| 事象 | 挙動 |
| --- | --- |
| 投影設定の読み込み失敗 | error を出し、**東京駅原点の固定値で続行**する。起動は止まらないため、誤った原点で生成した経路を配布し得る。LLH 系 CSV を使う環境では起動ログの投影原点を確認する |
| `config_yaml_path` が空 | error を出すが起動は続く。ブロック定義が無いため `/get_route` が失敗する |
| ブロック定義の読み込み失敗 | error を出し、空の状態で待ち受ける |
| 未知のブロック種別 | error を出し、そのブロックを無視する |
| 区間 CSV の読み込み失敗 | error を出し、その区間を空として扱う |
| `/get_route` の例外 | スタックトレースを error へ出し、空の経路と失敗を返す |
| `/update_route` の例外 | 同上。現在経路は更新しない |
| 封鎖エッジが見つからない | warn を出し、処理を続ける |
| 固定ブロックの封鎖 | warn を出し、現在経路と失敗を返す |
| 地図描画の失敗 | warn を出し、代替 PNG を返す |
| LLH と ENU の併記・不整合 | warn を出し、LLH を正本として続ける |

**ノードが停止する経路はない。** すべての失敗は応答の失敗フラグとログで表す。

### 6.6 ログ

`info`（起動時の設定内容、要求の受理）、`warn`（整合性の警告、代替処理）、
`error`（読み込み失敗、例外）を使い分ける。`debug` と `fatal` は使わない。

ラベル補完の通知のみ標準出力への出力であり、ROS ログに乗らない（7.4 節）。

`DiagnosticReporter` を使わない。**本ノードは健全性監視の対象に入っていない。**
サービスのみを持ち、要求が無い間は何も動かないためである。

## 7. 判定ロジックと閾値

### 7.1 グラフの構築

エッジ CSV の各行から、始点・終点・区間 CSV・双方向可否・重み係数を読む。

1. 各行を有向辺として登録する。双方向可の行は逆向きも同じ区間・同じ長さで登録する。
2. **双方向不可の行に対して逆向きの行が存在しない場合はエラーとする。** 片方向のみの
   通行を表すには、逆向きの行を別に用意して重みで差を付ける必要がある。
3. 有向辺を無向グラフへ畳む。同じ節点対に両方向の辺がある場合、**重みは 2 つの平均を
   取る。** 重み係数を方向ごとに変えても、探索では平均値が使われる。
4. 辺の重みは、区間 CSV の点列の実長に重み係数を掛けた値とする。実長は LLH 列があれば
   球面距離、無ければ平面距離で求める。

### 7.2 通過順序の最適化

端点集合を「開始節点 + 通過点 + 終了節点」とする。

1. 端点集合の各要素から Dijkstra 法で単一始点最短経路を求め、端点間の距離行列と
   経路表を作る。
2. **到達不能な端点対が 1 組でもあればエラーとする。** 向きの異なる対も個別に検査する。
3. Held-Karp 法で、開始節点から始まり終了節点で終わる、**すべての端点をちょうど 1 回
   通る**最小コストの順序を求める。終了節点は最後に来るよう制約する。
4. 得られた順序に沿って経路表の節点列を連結する。接続点の重複は 1 点に畳む。
5. 節点列の各隣接対について、登録した有向辺から区間 CSV と走行向き（順方向・逆方向）を
   決める。双方向不可の辺を逆向きに辿る必要がある場合はエラーとする。

**通過点は「通ってもよい点」ではなく「必ず通る点」である。** Held-Karp 法の計算量は
端点数に対して指数的（状態数 2^k × k）であり、端点数が増えると実行時間が急増する。
端点数の上限は検査していない。

**可変ブロックは通過点を 1 つ以上必要とする。** YAML の `checkpoints` と要求の
`checkpoint_labels` を統合した集合が空の場合、探索はエラーになる。`/update_route` では、
未通過の通過点が無くなった場合に終了節点を通過点として代入する。

### 7.3 区間の連結

連結時、前の区間の末尾と次の区間の先頭が同一座標（許容 1e-6 m）であれば 1 点に畳む。
由来情報の配列も同じ長さに保つ。畳んだ場合は、次の区間側の先頭に対応する由来情報を
落とす。

**由来情報と waypoint の長さが一致しなくなった場合はエラーとする。** 仮想区間の連結では
長さを明示的に照合する。

### 7.4 ラベルによる切り出し

`start_label` は**先頭から前方検索**、`goal_label` は**末尾から後方検索**で位置を決める。
空文字または未指定の場合は、それぞれ先頭・末尾を使う。

| 条件 | 扱い |
| --- | --- |
| ラベルが見つからない | エラー |
| 開始位置が終了位置より後ろ | エラー |
| 切り出し結果が 1 点以下 | エラー（1 点の経路を認めない） |

同じラベルが複数回現れる経路では、**開始は最初の出現、終了は最後の出現**が選ばれる。
周回経路で同じ節点を 2 回通る場合、意図しない広い範囲が選ばれ得る。

ラベルが空で補完した場合の通知は、ROS ロガーではなく標準出力への出力である。
`ros2 launch` のログには残らない。

### 7.5 姿勢の再計算

CSV が持つ姿勢をそのまま使う区間と、位置から計算し直す区間を分ける。

| 区間の種別 | 扱い |
| --- | --- |
| 仮想区間 | **全点を再計算** |
| CSV の向きと逆に辿る区間 | **全点を再計算** |
| CSV の向きどおりに辿る区間 | CSV の姿勢を維持 |
| ブロック境界の末尾点 | その点のみ再計算 |
| 経路全体の末尾点 | その点のみ再計算 |

再計算は、各点から次の点へ向かう方向を yaw とする。区間の末尾点は、1 つ前の点から
その点へ向かう方向を使う。

逆走区間を再計算するのは、CSV の姿勢が採取時の進行方向を向いており、逆向きに辿ると
180 度ずれるためである。

### 7.6 封鎖再探索の起点

走行中エッジの両端点のうち、**由来情報の `edge_u` を無条件に再探索の起点とする。**
`edge_u` は経路生成時に「prev 側の端点」として記録しているため、走行方向に対して常に
手前側の節点である。

CSV の向きと走行向きの一致を表すフラグは、**起点がどちらの端点かを判別する指標には
ならない。** このフラグは仮想区間で局所 index を読み替えるためだけに使う。

**固定ブロックは再探索の対象外である。** 固定区間で封鎖が報告された場合、warn を出して
失敗を返し、現在経路をそのまま応答へ入れる。固定区間は代替経路を持たないため、探索の
余地がない。

### 7.7 未通過通過点の判定

1. YAML のブロック通過点と、直近の `/get_route` 要求の通過点を統合する。
2. そのうち、対象ブロックの節点として存在するものだけを必須集合とする。
3. 現在経路の先頭から `prev_index` までの各点のラベルを見て、必須集合に含まれるものを
   通過済みとして履歴へ加える。
4. 必須集合から履歴を引いた差を、再探索の通過点とする。
5. 差が空の場合は終了節点を通過点として代入する（7.2 節の制約を満たすため）。

履歴はブロックごとに保持し、`/get_route` の成功でリセットする。**封鎖が複数回起きても、
一度通過した点を再度必須にしない。**

### 7.8 仮想区間の生成

現在位置から再探索の起点（U）へ戻る点列を、走行中エッジの CSV から切り出す。

1. 走行中エッジの CSV を区間キャッシュから取り、U のラベルを持つ点を探す。
2. **U が CSV の先頭か末尾のいずれかであることを要求する。** 中間に見つかった場合は
   エラーとする。末尾であれば点列を反転し、U を先頭に揃える。
3. 由来情報の局所 index を、U を先頭とした向きへ読み替える。
4. 読み替えた位置の点が prev の座標と一致するかを確認する。一致しない場合は座標一致で
   全体を走査し直す。見つからなければエラーとする。
5. 現在位置の点を先頭に置き、prev の点を続け、prev の位置から index 0（U）まで 1 ずつ
   戻る点列を連結する。
6. 端点ラベルを「`current`」と U のラベルで刻む。

現在位置の点は姿勢を持たないため、仮想区間は全点が姿勢再計算の対象になる（7.5 節）。

**この点列は後退する指令ではない。** 現在位置から U へ向かう前進経路として組み立てる。

### 7.9 地図への重畳

ワールドファイルから緯度経度と画素座標の対応を作り、節点と探索結果の経路を地図画像へ
描く。地図リソースが無効な場合、または描画に失敗した場合は、文字列を描いた代替 PNG を
返す。地図リソースが指定されているのに描画に失敗した場合は warn を出す。

### 7.10 LLH と ENU の整合性検査

CSV に LLH と ENU が併記されている場合、LLH を正本として次の 3 点を検査する。閾値を
超えると警告を出すが、処理は続ける。

| 検査 | 閾値 |
| --- | --- |
| LLH から再計算した水平位置と、記載の `x`,`y` の差 | 0.10 m |
| 記載の `z` と 0.0 の差 | 0.30 m |
| 記載の四元数から求めた方位と、記載の方位の差 | 1.0 deg |

## 8. 並行性・周期・起動・依存関係

### 8.1 並行性と応答時間

タイマーを持たない。処理は要求を受けた時のみ行う。

2 つのサービスを**同一の相互排他コールバックグループ**に置く。`/get_route` と
`/update_route` が同時に走ると、ブロック定義・区間キャッシュ・グラフ・現在経路を
同時に書き換えるため、直列化する。

**経路生成は同期的に完了する。** 探索・CSV 読み込み・画像描画をサービスコールバック内で
行うため、応答までの時間は経路の規模と端点数に比例する。要求側のタイムアウトは
`route_manager` 側が持つ（
[route_manager 詳細設計書](../../route_manager/docs/route_manager_詳細設計書.md)
7.5 節）。

### 8.2 起動

entry point は `route_planner` である。launch の引数は [README](../README.md) を正とする。

launch はパラメータファイルの差し替えと、サービス名 2 個の remap を引数で指定できる。
サービス名は相対名で宣言するため、namespace の付与でも変更できる。

起動時に CSV・YAML・地図を読み込む。**読み込みの失敗で起動は止まらない**（6.5 節）。
終了時に解放する外部資源はない。

### 8.3 依存関係

`ament_python` でビルドする。

| 依存 | 用途 |
| --- | --- |
| `rclpy` | ノード |
| `tc_route_msgs`、`tc_geo_msgs` | サービスとメッセージ |
| `geo_pose_converter` | LLH と ENU の変換、投影設定の読み込み |
| `std_msgs`、`geometry_msgs`、`sensor_msgs` | メッセージ |
| `python3-networkx` | グラフ構築と最短経路 |
| `python3-matplotlib`、`python3-japanize-matplotlib` | 地図への重畳描画 |
| `python3-yaml` | ブロック定義の読み込み |

`geo_pose_converter` は ROS パッケージだが、`geo_pose_converter.geo_core` を通常の
Python ライブラリとして import する。install 後も同じ経路で解決する。

`networkx` が無い環境では可変ブロックの探索が ImportError になる。固定ブロックのみの
経路は `networkx` 無しでも生成できる。

## 9. 確認方法と未確認範囲

### 9.1 自動確認

`tests/` の 3 ファイルが ROS 非依存で動く。

| 試験 | 固定する内容 |
| --- | --- |
| `test_graph_solver_llh.py` | `latitude` / `longitude` ヘッダの CSV を地理座標として扱い、球面距離で長さを求める |
| `test_route_builder_llh.py` | CSV の LLH・高度・方位が内部表現へ保持され、書き出しで往復する |
| `test_route_builder_slice.py` | ラベルによる切り出しの境界 |

`test_route_builder_slice.py` は `yaml` と `matplotlib` を差し替えて import する。
切り出し処理だけを対象とし、地図描画と YAML 読み込みを実行しないためである。

### 9.2 手動で確認する範囲

- ブロック定義と CSV を配置し、`/get_route` が経路を返すこと
- 固定のみ・可変のみ・混在の 3 構成
- 通過点の指定（YAML・要求の両方、重複を含む）
- 逆走区間の姿勢が反転していること
- ラベルによる切り出し（先頭・末尾の補完、未存在、順序逆転、1 点）
- `/update_route` の検証（版不一致、非隣接、ラベル不一致、別ブロック）
- 封鎖再探索（可変区間での代替経路、固定区間での失敗）
- 封鎖が複数回起きた場合の通過点履歴
- 地図リソース有り・無し・片方のみでの画像生成

### 9.3 未確認範囲

- **生成した経路で実機走行し、経路の通行性を確認した範囲は限られる。** 同梱のつくば
  経路は検証用であり、現地確認済みの本番経路として扱わない。
- **端点数に対する探索時間を測定していない。** Held-Karp 法は指数的であり、通過点を
  増やした場合に `route_manager` のタイムアウトを超えるかは未確認である。
- 投影設定の読み込み失敗時に固定値へ落ちる挙動（6.5 節）が運用でどう現れるかを確認して
  いない。
- 封鎖エッジがノード再起動まで戻らない点（5.2 節）の運用上の影響を確認していない。
- 同じラベルが複数回現れる周回経路での切り出し（7.4 節）を確認していない。
- 双方向で重み係数が異なる辺の扱い（7.1 節の平均）を確認していない。
- `tools/` の各スクリプトは経路整備時に手で動かすだけで、自動確認していない。

## 10. 影響範囲・未決事項

### 10.1 影響範囲

`tc_route_msgs` の `Route`、`Waypoint`、`GetRoute`、`UpdateRoute`、および `tc_geo_msgs` の
`MapProjection` に依存する。フィールドの変更は `route_manager` と `route_follower` にも
同時に影響する。

版の扱い（3.2 節）は `route_manager` の `major` / `minor` 表現と対になる。どちらかを
変える場合は両方を同時に更新する。

CSV の列仕様を変える場合は、`routes/` 配下の全環境のデータ、`route_survey` の出力形式、
`tools/segment_waypoints.py` を併せて更新する。

投影条件は `geo_pose_converter` の parameter YAML を正とする。原点を変更する場合は、
既存の LLH 系 CSV から生成される ENU 座標がすべて変わるため、走行側の自己位置の原点も
同時に合わせる。

### 10.2 未決事項

| 件 | 選択肢 | blocker |
| --- | --- | --- |
| 6.5 節: 投影設定の読み込み失敗が起動を止めない | 起動を失敗させる／LLH 系 CSV を使う時点で失敗させる | ではない。LLH 系 CSV を使う環境では誤った原点の経路を配布し得る |
| 5.2 節: 封鎖エッジの復旧手段がない | `/get_route` でグラフを再構築する／封鎖の解除を受け付けるサービスを設ける | ではない。再起動で復旧できる |
| 7.2 節: 探索の計算量に上限検査がない | 端点数の上限を設ける／探索を打ち切る | ではない。`route_manager` のタイムアウトが実質の上限になっている |
| 7.1 節: 双方向の重み係数が平均される | 有向グラフで探索する／方向ごとに係数を変えない運用を明示する | ではない。現在のデータでは方向ごとに係数を変えていない |
