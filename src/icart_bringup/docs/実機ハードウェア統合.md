# 実機ハードウェア統合

## 構成と設定の正本

ROS 2 Jazzy上で、センサ・車輪・GNSS/LIO融合・経路処理・操作UIを
`icart_bringup`から起動する。接続先と取付位置は
[`params/hardware.yaml`](../params/hardware.yaml)に集約する。
`prepare_real_session`は設定をセッションへコピーするため、ソースを変更しても
生成済みセッションには反映されない。設定を変更した場合は新規出力先へ再生成する。

| 機器 | ドライバ・出力 | 同梱実機設定 |
| --- | --- | --- |
| 車輪 | YP-Spur coordinator → ypspur_ros2、`/ypspur_ros/odom` | `/dev/serial/by-id/usb-T-frog_project_T-frog_Driver-if00` |
| URG | urg_node_driver → `/scan` | `/dev/serial/by-id/usb-Hokuyo_Data_Flex_for_USB_URG-Series_USB_Driver-if00`、角度±2 rad |
| MID-360 | Livox → `/mid360/livox/lidar`、`/mid360/livox/imu` | PC `192.168.1.5`、LiDAR `192.168.1.201` |
| GNSS | UM982 → `/rtk_gps/{fix,heading,rtk_status}` | `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`、115200 baud |
| カメラ | usb_cam → `/usb_cam/image_raw` | C920、640×480、5 fps、YUYV |
| Joy | joy_node → manual_teleop → cmd_vel_mux | `Sony PLAYSTATION(R)3 Controller`、SDLのPS番号10 |

これらの公開名はGUI・融合・採取・記録の接続先と共通にする。
GNSS単独診断は `gnss.launch.py` で場所と補正局を指定し、実機共通起動と同じカタログを使用する。
MID360単独の `msg_MID360_launch.py` も `/mid360/livox/{lidar,imu}` に配信し、
`mid360_frame`を使用する。FAST-LIOの`mid360.yaml`はこの点群・IMUを購読する。
`rviz_MID360_launch.py`は同じ公開名のPointCloud2を表示する診断用で、FAST-LIO用のCustomMsgとは形式が異なる。
共通起動や別の診断と同じ受信機を二重起動しない。

センサが未接続の場合、配線設定の一致を実データ受信済みとは扱わない。
車輪・URG・C920・PS3 Joy・MID360の全接続状態での走行・停止確認は、実車で別途行う。

カメラの設定値は `/dev/v4l/by-id/usb-046d_HD_Pro_Webcam_C920_B8DE396F-video-index0`。
launchは起動時にリンク先を解決し、デバイスが存在しなければエラーにする。
別カメラへ自動切替しない。画像認識ノードは別途起動する。
カメラの内部・外部較正値はこの設定で提供しておらず、未較正の画像から距離を確定しない。

車輪パラメータは `package://ypspur_ros2/config/icart-middle.param` を使う。
coordinatorの線加速度上限は1.5 m/s²、ROS側の通常加速は0.7 m/s²、減速は1.5 m/s²、
角加速度は1.5 rad/s²である。速度指令はドライバで1.0 m/s・1.0 rad/sに制限される。
制限値と生存監視は[ypspur_ros2](../../ypspur_ros2/README.md)を参照する。

## センサ配置と座標

`base_link`は車軸中心、x前・y左・z上とする。以下は同梱設定値であり、
機体の組み替え後も同じ較正が有効という意味ではない。

| 原点 | x [m] | y [m] | z [m] | 姿勢 |
| --- | --- | --- | --- | --- |
| MID-360 LiDAR | 0 | 0 | 0.414 | roll −0.6°、pitch +26.9°、yaw 0° |
| UM982主アンテナ ANT1 | −0.30 | 0 | 0.564 | 車軸後方30 cm |
| UM982副アンテナ ANT2 | −0.45 | 0 | 0.564 | 主アンテナ後方15 cm |
| URG | 0.075 | 0 | 0.49 | 水平 |

アンテナ高さはLiDAR原点の鉛直上15 cm。アンテナ間隔は0.15 mで、
融合の基線長許容範囲は設定間隔の0.7〜1.3倍（0.105〜0.195 m）として生成する。
ANT1→ANT2の方位から車体前方を得る補正は180°。
受信機側で方位補正を行う場合は二重補正を避ける。

FAST-LIO内部のLiDAR→IMU較正は `extrinsic_T=[-0.011,-0.02329,0.04412]`、
`extrinsic_R=I`。車体への取付角はここに加えず、オンライン外部較正は既定で無効とする。
車体→IMU位置を `p_BI=p_BL-R_BI*p_IL` で導出し、融合で
`R_WB=R_WI*R_BI^T`、`p_WB=p_WI-R_WB*p_BI` を用いる。
主アンテナのレバーアームも車体姿勢で回転して補正する。

FAST-LIOの `/lio/odometry_raw` を重力基準で水平化した `/lio/odometry` が
融合・採取の共通入力となる。基準確定には約2秒の静止を要する。
詳細は[GNSS/LIO融合](../../gnss_lio_fusion/README.md)を参照する。
融合が配信するmap→base_linkは平面TF。FAST-LIOのcamera_init→bodyは別系統であり、
bodyとbase_linkを静的に直結しない。

## PS3コントローラ

実機共通起動は `hardware.yaml` のSDL割当を適用する。
単体drive_mode_managerのPS番号16とは異なるため、単体起動時は設定を合わせる。

| 操作部 | Joy番号 | 機能 |
| --- | --- | --- |
| 左スティック上下／左右 | axes 1／0 | 前後／旋回。手動入力の倍率は1.2 m/s／1.5 rad/s |
| L1 | buttons 4 | 保持中だけ手動入力を有効にする |
| R1 | buttons 5 | 保持中だけ融合へのGNSS入力を遮断する途絶模擬。ターボは無効 |
| PS | buttons 10 | L1と2秒長押しで自律→手動 |
| × | buttons 0 | 経路採取開始 |
| ○ | buttons 1 | 一時停止点の属性を記録 |
| △ | buttons 2 | 信号停止点の属性を記録 |
| □ | buttons 3 | 経路採取終了 |

通常運用では、手動中にL1を離して1秒後、自律指令が新鮮なら5秒の待機を経て自律復帰する。
経路採取では手動固定で、自律復帰しない。○・△・□は車体停止指令ではなく、PSも非常停止ではない。
手動入力の小さな前後揺れは `in_place_turn_deadzone=0.12` で除き、その場旋回しやすくする。
R1を離すかJoy受信が0.5秒途絶えると模擬を解除する。生GNSS・NTRIP通信・記録は継続する。

## 接続準備

依存は `rosdep install --from-paths src --ignore-src -r -y` で導入する。
シリアルの読み書き権限と実デバイスの対応を確認する。同型機を複数接続する場合は
by-id名だけで識別できないことがある。ネットワーク設定はOS側で管理する。

```bash
# インターフェース名は使用するPCに合わせる。同名接続がある場合は既存設定を確認する。
nmcli connection add type ethernet con-name mid360-direct ifname <有線インターフェース> \
  ipv4.method manual ipv4.addresses 192.168.1.5/24 ipv4.never-default yes \
  ipv6.method disabled connection.autoconnect yes
nmcli connection up mid360-direct
```

実機共通起動はNTP→PC→software PTP→MID-360の同期成立を待ってから走行系を起動する。
サービス準備とゲートの条件は[共通起動設計](共通起動設計.md)を参照する。
セッションに必要なファイルが不足する場合は、ドライバ起動前の検査でエラーにする。

## 地域・補正局

[`params/rtk_stations.yaml`](../params/rtk_stations.yaml)の登録設定を選択する。
一覧への登録は、利用時点の配信や現地FIXを保証しない。

| site | station | mountpoint |
| --- | --- | --- |
| inagi | tokyo_6c10214a（既定） | 6C10214A |
| inagi | tokyo_c4cae992 | C4CAE992 |
| tsukuba | tsukuba_takashima（既定） | 3041F3CA |
| tsukuba | joso_yasuda | 10D85AA2 |

`none`（補正なし／外部補正）と `custom` も選択できる。
採取時と走行時は同じ局と座標基準を使い、局を変える場合は既知点で位置差を確認する。
WGS84上のENU変換だけでは、測地成果や元期・今期の差を補正できない。

```bash
ros2 run icart_bringup check_rtk_station --site inagi --list
ros2 run icart_bringup check_rtk_station --site inagi --station tokyo_6c10214a
```

`--list` は登録内容の表示、局を指定した検査は短時間のRTCM受信を行う。
CRC一致フレーム数と種別を表示し、無受信時は終了コード1となる。
シリアルポートや車輪は操作しない。NTRIPはv1/plain TCPで、TLS・HTTP chunked必須のサービスは非対応。
CRC不一致を転送せず、有効RTCMが15秒来なければ再接続する。

## セッション生成・採取・走行

```bash
ros2 run icart_bringup prepare_real_session \
  --site inagi --station tokyo_6c10214a \
  --hardware <運用用hardware.yaml> --output <新規実機sessionディレクトリ>
```

出力はsession.yaml、hardware.yaml、geometry.yaml、um982.yaml、livox.json、fastlio.yaml、
fusion.yaml、recorder.yaml、projection.yaml、routes/、station.yaml。
認証情報を含むum982.yamlは0600、セッションディレクトリは0700とする。
`custom` は `host, port, mountpoint, user, password` を持つYAMLを
`--ntrip-config`で指定する。認証情報はGitへ追加しない。

同梱fixed経路には `route_review_required` が付く。現地確認済み経路として扱わない。
原点は経路先頭のLLHで、高度未提供時は0 mを計算原点とする。
`--route-directory <採取先>` を指定すると、選択したCSVとprojection.yamlを引き継ぐ。

```bash
export ROS_DOMAIN_ID=0
ros2 launch icart_bringup survey.launch.py \
  environment:=real session:=<実機session>/session.yaml \
  output:=<新規採取先> joy_input:=joy_node
```

採取中は手動固定。既にJoyを配信している場合は `joy_input:=external` を使う。
終了後、経路と回避幅・停止属性を確認し、走行用セッションへ切り替える。

```bash
ros2 run icart_bringup run_session \
  --session <走行session>/session.yaml --environment real --start-ui
```

起動後はmanual_start待ち。CLIが起動したスタックをUIから重複起動しない。
GUIの「実機／自律走行」では `recorded_route.launch.py` の `route_directory` に
終了済み採取フォルダを指定する。隣接sessionから設定を引き継ぎ、走行用にコピーする。
アンテナ位置等はGUIで走行用の値を指定でき、採取原本は変更しない。

実機自律走行では障害物ヒント未受信・1秒の途絶で指令をゼロにする。
手動指令はL1のdeadmanを使い、自律側の融合減速・障害物監視を通らない。
車輪のMotionLimits生存監視は[robot_navigator](../../robot_navigator/README.md)を参照する。
coordinator起動後の2秒待ちは接続準備完了の保証ではない。
主要ドライバ終了時は共通launchを終了する。

## FAST-LIOの地図設定と確認範囲

実機設定は近距離除外 `preprocess.blind=0.7` m、局所地図 `cube_side_length=2000` m、
`det_range=100` m、点群間引き0.5 mを使う。局所地図は自己位置推定用で、
`/Laser_map` の累積表示地図とは別である。表示更新は1秒、bag用の地図記録は10秒間隔。
地図保持点数が増えるとメモリ負荷も増える。

設定・座標変換・起動構成は `tests/` で確認する。実機では接続・方位・時刻・
車体寸法・停止距離を別途確認する。地面検出やシミュレーションの成立だけで、
歩道の通行性や実コース完走を認定しない。
