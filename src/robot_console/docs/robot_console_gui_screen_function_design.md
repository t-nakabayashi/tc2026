# robot_console 画面・機能詳細設計書

## 画面構成

MainWindowはPyQt5の7タブで構成する。ScaledCanvasで画面全体を拡縮する。
通常の運行監視と操作はダッシュボードに集約し、詳細情報は対応タブで確認する。
実機の時刻同期警告は全タブの上部に表示する。

| タブ | 表示・操作 |
| --- | --- |
| ダッシュボード | 運行フェーズ、Route/Follower、Drive/CmdVel、GPS/Pose、イベント、Node Health、Manual Ops、起動操作、bag保存 |
| 自己位置・センサ情報 | 経路・自己位置・目標の地図、センサ画像、カメラ認識表示 |
| 起動・設定 | 環境・運転モード、プリセット、候補／起動予定、config・引数編集、記録ルート選択 |
| コンソールログ | profileごとのプロセス状態・stdout/stderr・保存ログ |
| GNSS・基地局 | GNSS品質、アンテナ方位・基線長、局情報、RTCM通信状態 |
| ルート記録 | ICP／GNSS融合の採取状態、開始／終了、点数、左右幅候補・理由、保存中／完了／エラー |
| 地図作成 | bag選択、FIX・ICPグラフ生成、進捗・中止・結果再表示、俯瞰確認、次回ICP走行・ルート記録への地図設定 |

## 実機の操作フロー

1. 起動・設定で「実機／手動走行」を選び、プリセットを適用する。
2. 場所・RTK局・保存先とICP地図を確認し、重複する起動構成を停止する。既定地図はつくばのFIX拘束地図。
3. ダッシュボードで一斉起動し、ICPの初期化と自己位置の受信を待つ。初期値は良好FIX＋方位または手動設定を使う。
4. ルート記録で開始し、L1を保持して操縦する。停止属性はコントローラから記録する。
5. 車体を停止して終了・保存を行い、保存完了を確認する。
6. 採取構成を停止し、「実機（ICP）／自律走行」またはGNSS系の「実機／自律走行」で保存ルートを選ぶ。
7. 経路・原点・設定・幅未確認点を確認して起動し、始点付近でmanual_startを送る。

「実機（融合）／手動走行」または自己位置設定 `gnss` でGNSS融合による記録を選べる。
ICP照合不良中はLIO予測を要確認として記録し、自動幅を0にする。LIO途絶時は新しい点を追加しない。
保存は別ワーカーで行い、終了時の書込み成功まで保存完了と表示しない。エラー時は終了・保存で再試行する。
記録開始／終了は速度指令を出さない。終了は位置途絶中も可能で、保存失敗は完了と表示しない。
採取状態が3秒届かなければ未接続に戻し、操作を無効にする。
採取中・2点未満・必要ファイル欠落の経路は自律起動に使わない。

## ダッシュボードの入力

Manual Opsからmanual_start、sig_recog、road_blocked、固定障害物ヒント、静止画像入力を送れる。
manual_start=trueは開始・停止点からの再開、falseは入力解除であり走行停止ではない。
実際の手動介入はdrive_mode_managerのL1＋PSを使う。
固定障害物ヒントは停止操作で解除し、通常のobstacle_monitorへ戻す。

ROSBAGは記録開始後に停止・保存し、metadataを含む保存完了を待つ。
詳細は[記録仕様](rosbag_ui.md)を参照する。

## 地図とセンサ

地図はactive_routeのLLHを表示する。未走行は緑、走行済みは灰、現在位置は水色、目標は黄色。
初回受信・形状変更で全体表示し、進捗更新では手動の拡大率を維持する。
「ルート全体」で表示範囲を戻せる。最大zoomは22、19超は背景タイルを拡大表示する。
GNSS単独方位は北基準時計回り、融合yawはmap基準反時計回りと明示する。

画像列は上からフロントカメラ、Sensor Viewerの順に縦積みとし、QtとHTMLで順序を揃える。
実機カメラはusb_camの `/usb_cam/image_raw`。道路封鎖・信号の認識ノードは画像を配信せず、
`/perception/*/overlay` の検出矩形・判定をConsoleCoreが同じカメラへ重畳する。
採用検出は太線、採用外は細線・灰色、フレームとの時刻差が大きい枠は破線とする。
直近の認識枠は保持期限内で後続フレームにも描画する。
GO/STOP・封鎖状態とstatus_noteは画像直下の判定チップに表示し、未受信でも枠を残す。
Qtの地図と画像列の横比は3:2、画像列内のカメラとSensor Viewerの行高比も3:2。
HTMLはカード幅に上限を設けて中央に置く。
画像表示の有無だけで認識結果やセンサ較正の有効性を判断しない。

## 警告と表示上の制約

R1によるGNSS途絶模擬は赤、通知期限切れは黄で表示する。
実機時刻同期は未成立・喪失を全タブで警告し、復旧後は共通構成を再起動する。
GNSS/NTRIPの未受信・期限切れの数値は正常色で表示しない。

画面モデルに存在しても、以下の値は運用判断の根拠にしない。

- signal_stop_active／line_stop_activeは停止属性からの導出が未実装で、既定値のままである。
- within_arrival_thresholdは到達閾値を受信して算出する機能がない。
- Node Healthのlast_log_levelとrequired_but_not_selectedは実際の警告判定を網羅しない。

停止理由は経路属性・follower状態・ログを併せて確認する。
プロセスのRUN数は起動グループ数であり、すべてのセンサが正常なことを表さない。

## HTML遠隔観測と確認方法

HTMLはSnapshotによる読取専用表示で、走行・起動停止・bag・採取操作は提供しない。
GNSS詳細は折りたたみ、スマートフォン幅でも接続先を折り返す。
HTTPサーバはloopbackで待ち受け、認証機能を持たない。
別端末への公開は[公開範囲の運用](html_ui_access.md)に従う。
PC内URLは遠隔端末から直接開ける共有URLではない。

表示元の構造は[アーキテクチャ](robot_console_gui_architecture_design.md)、
操作手順は[README](../README.md)を参照する。
`tools/tests/` と `tools/check_qt_entry.py` でSnapshot・各画面・実ROS受信を確認する。
