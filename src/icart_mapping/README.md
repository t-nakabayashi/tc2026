# FIX・ICP地図作成

通常版robot_consoleの「地図作成」で、SQLite3形式のROS 2 bagディレクトリを選び、
「地図作成開始」を押す。初期値はつくば全コースの結合bagである。
分割db3はmetadata.yamlの順で全て読む。記録済みFAST-LIO raw姿勢、Livox CustomMsg、
IMU、NavSatFix、RtkStatusが必要。生IMUからFAST-LIOを再実行する機能ではない。

点群の歪み補正、重力整列、相対移動グラフ、GICP区間接続・双方向検証付きループ閉合、
FIX水平位置拘束、点群再構築を順に実行する。FIXは状態4、衛星20以上、0<HDOP<=1、
補正齢0〜1.5秒、fix/status差0.05秒以内、キーフレーム時刻差0.15秒以内を選ぶ。
連続する拘束は1秒以上、移動2 mまたは10秒以上離す。アンテナ取付位置を反映し、
水平標準偏差0.2 m・Huber係数1.345で重み付けする。値は精度の保証ではない。
高さと傾きはLiDARグラフを保ち、GNSS高度・方位は拘束に使用しない。
初期車体高さを0とする相対高さである。出力は指定のprojection.yamlと同じENU原点を使う。

進捗バーは処理段階の目安で、残り時間の割合ではない。完了時に俯瞰画像、点数、
FIX・ICP拘束数、採用FIXとの差を表示する。この差は最適化に使った点での残差で、
独立した精度評価ではない。「ICP走行の地図に設定」は次回のICP走行とルート記録の地図を指定するだけで、
稼働中の推定器や走行を変更しない。利用者が地図と経路原点を確認して走行構成を起動する。

出力とログは/media内の新規map日時フォルダへ保存する。既存bag・地図・経路を変更しない。
map_manifest.json、NPY/PCD/PLY点群、軌跡CSV、overview.png、拘束・最適化JSON、
入力SHA256、job.json、status.json、build.log、work内の抽出・点群キャッシュを保存する。
UI再起動後は「結果を開く」で出力フォルダを選べる。未完了・失敗・中止は地図設定に渡せない。

処理はbubblewrapでネットワーク・実機デバイスを隔離し、ジョブ出力先だけを書込可能にする。
ROSノード・ドライバ・bag再生は起動しない。既存の専用venvのGTSAMとsmall_gicpを使い、
共通Python環境へ追加インストールしない。専用環境・取付・投影は「詳細設定」で選ぶ。
入力不足、非対応形式、座標設定不一致、FIX不足、ICP接続・ループ不成立は失敗として停止する。
「中止」またはGUI終了で処理群を終了する。修正後は新規ジョブで再実行する。
地図は観測した点群であり、通行可能領域・未観測領域・実機走行の安全性を保証しない。

## 確認範囲

つくば全コース結合bagの23分割ファイルから、抽出・ICP閉合・FIX拘束・地図出力を
隔離環境で確認している。2,179姿勢、FIX149拘束、ICP接続3件・ループ16件、
約368万点を生成した。通常版GUIでの完成結果表示・次回地図への設定・中止・
入力不足の失敗表示、ICP推定器での読込と同一データの照合を確認している。
自動テストはジョブ管理・GUI・既存起動設定を対象とする。
全コースの観測時間50分50秒に対する地図作成の実測は約428秒（約7分8秒）。
Core Ultra 7 258Vでの1回の測定で、入出力媒体・点数・ループ候補数に依存する。
生成地図による実機走行、独立した測量真値に対する精度は未検証である。
