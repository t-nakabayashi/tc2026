# 方位推定とUI接続の確認方法

## 方位の基準

受信機headingは真北から時計回り、融合yawはmapの+xから反時計回り。
前ANT1・後ANT2配置では共通起動が180°補正する。
受信機設定、IMU取付角、重力基準、map回転を確認し、補正を二重適用しない。
[取付と座標](../../icart_bringup/docs/実機ハードウェア統合.md)を参照する。

## 品質判定と確認条件

位置更新と方位更新を分離する。FIX/FLOAT以外、方位σ不明・過大、衛星不足、基線長不適格、
大きな方位反転を採用しない。±πの折返しは最短角で判定する。
異常LIO後の方位再取得は良好な連続観測と補正速度上限を使う。
時刻が逆行したLIOや水平基準が変わった観測に、古い融合履歴を混ぜない。
具体値は[詳細設計](gnss_lio_fusion_詳細設計書.md)を参照する。

`tests/` で静止・旋回・反転・σ欠落・LIO異常後の再取得・車輪退避を確認する。
模擬走行の方位故障はevaluate_terrain_trial.pyの
`--heading-fault`、`--heading-fault-after`、`--heading-fault-duration`で指定する。
位置誤差と方位誤差、センサ入力と採用した相対運動を別々に記録する。

## UI・初期化・停止

GUIはGNSS方位・融合yaw・方位σ・baseline・modeを区別する。
重力整列待ちはWAIT_ALIGNMENT、初期FIX待ちはWAIT_INITIAL_FIXとし、自律指令を0にする。
R1模擬は生GNSSの通信とは別の警告で表示する。

模擬ではROS時計、実機受信監視では単調時計を使う。
UI単独起動とCLI同時起動を区別し、profileの二重起動を避ける。
Snapshotと正式Qt入口の確認はrobot_console/tools/testsとtools/check_qt_entry.py、
共通起動との接続はicart_bringup/tools/evaluate_console_session.pyを使う。

方位の誤差抑制だけでは歩道内の通行を保証しない。
経路横ずれ、車体領域、停止・復帰、入力喪失を同じ走行で確認する。
