# 空き空間参照サンプル

## 目的と位置づけ

GNSSの品質が落ちた際、誤差を含むルートへの横方向の追従を弱め、ルートの進行方向と
周囲の空間に沿って進む考え方を評価する。自己位置のドリフトそのものを修正する方式ではない。
地図への再位置合わせ、分岐選択、停止線・終点の判定は別途必要。

本サンプルはROS bagを読み、候補経路と診断値をファイルへ出力するだけである。
ROSノード作成・速度publish・実機制御・起動設定変更は行わない。
人工歩道での比較対象は単純なpure-pursuitモデルで、現行robot_navigatorの再現ではない。

## ファイル

- `route_survey/free_space_core.py`: 点群から局所グリッドを作り、車体の通過範囲を確認した円弧を採点。
- `tools/evaluate_free_space.py`: bag読込、再生評価、人工環境での閉ループ計算、画像出力。
- `tests/test_free_space.py`: 閉塞・狭路・欠測・古い観測・大きな方位差などの回帰試験。

## 手法

1. 重力方向を補正したLIO座標で直近6秒の地表面を蓄積。GNSSの位置補正を局所点群へ混ぜない。
2. 局所平面・高さ・反射強度から、観測済み地表、材質変化/粗面、落下側、不明を区別。
   2.5 cmボクセルで重複を除き、15 cmセルに3点以上の地表面観測を要求する。
3. 現在のMID360の地面より高い点とURGを別の障害物層として重ねる。
   人が来たことだけで既に見た舗装面を消さない。物体が現在占めている場所は進路候補から除く。
4. 41本の円弧を最大3 m、5 cm以下の間隔で評価。半径0.40 mの円形車体＋余裕を想定。
   グリッドの離散化・サンプル間隔も考慮し、車体が未観測・材質拒否・障害物セルにかかる候補を棄却。
5. 残った候補を、ルート方向への進捗・周囲の余裕・弱い横位置追従・前回の曲率からの変化で採点。
   不確かさが大きいほど横位置への追従を弱める。サンプルの位置標準偏差は0.8 m固定。
6. 前方に1 m以上の候補を確保できなければ停止。観測が0.5秒以上古い場合や、
   ルート方位が前方±65°を外れる場合も停止。候補速度の上限は0.35 m/s。

出力速度は診断用の提案値であり、加速度制約を含む実機制御器ではない。
歩道の判別には反射強度の環境依存の閾値が残る。障害物がないことは歩道であることを意味しない。

## 実行

ROS 2 Jazzyとこのワークスペースをsourceする。NumPy、SciPy、Matplotlib、OpenCVが必要。

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
PYTHONPATH=src/route_survey:src/gnss_lio_fusion:$PYTHONPATH OPENBLAS_NUM_THREADS=1 \
  python3 src/route_survey/tools/evaluate_free_space.py \
  --bag <ROS-bagディレクトリ> \
  --output <新規評価ディレクトリ>
```

初回は新規出力先を使う。同じbagを同じ設定で再評価するときは`--bag`に代えて
`--reuse-cache`を指定する。人工環境だけなら`--synthetic-only --output <新規出力先>`で実行できる。
キャッシュは最初に指定したbagの内容であり、異なるbagへ再利用しない。

ツール内に固定された取付値は、MID360のroll=-0.6°/pitch=26.9°、IMUレバーアーム
[-0.0102608953813, 0.0228267078793, 0.3694617699794] m、URG前方0.075 m。
hardware.yamlの変更は自動反映されない。取付・車体が異なる場合は、これらと車体形状を合わせる。
URGは既存`obstacle_monitor`と同じく、センサ原点から20 cm未満の近接反射を除く。
これを外部空間の観測済み判定へ使うことはない。

## 評価方法と制約

人工歩道では幅2.4 m・長さ12 mの直線を使い、横位置バイアス5通りと方位バイアス3通りを組み合わせる。
0.1秒ごとに位置と局所地図を更新し、真の歩道境界と円形車体で逸脱を判定する。
閉塞・未観測のケースと、舗装・芝生を同じ平面にした材質の反例も生成する。
人工地図には認識誤りや通信遅延を入れていないため、実環境での性能指標ではない。

bag再生は冒頭10秒を除き、約1秒間隔で記録済みの局所地図から候補を選ぶ。
記録上RUNNINGかつ車輪速度の絶対値が0.05 m/s超の場面を走行場面として集計する。
ルート参照に横位置{-1,0,+1} m、方位{-10,0,+10}°を加えた9変種でも候補を比較する。
別の進路を実際に走る閉ループ試験ではなく、完走率や衝突回避率を測るものではない。

- 重力回転はbag内で成立した最初の静止観測から求め、全場面へ適用する事後解析。
  校正より前の場面も含むため、オンライン初期化の動作確認にはならない。
- カメラ画像は目視照合用。点群への投影や画像による材質分類には使わない。
  物理的な歩道幅・境界精度の評価には校正と正解データが必要。
- 平らな芝生と舗装の反射強度が似る場合、幾何と強度だけでは両者を区別できない。
  本出力は歩道の意味分類や恒久的な歩道全幅ではない。
- 分岐・到着・停止線の判定は対象外。LIOのドリフト自体も補正しない。
- `analysis_ms` は局所地図と9変種の候補評価に要する時間で、bag読込・画像生成を除く。
  センサ入力から出力までの実時間処理性能を示さない。

## 出力

`replay.json`（各場面と±1 m/±10°の9変種）、`replay_summary.json`、
`synthetic.json`、`synthetic_summary.json`、`material_counterexample.json`を保存する。
`synthetic_comparison.png`は人工環境の軌跡比較、`example_*.png`は実画像と局所空間の対応図。
緑は地表候補、赤は現在の障害物、茶色は材質/粗面での拒否、紫は下方段差、灰は未観測。

ファイルとPNGは作業PC内に保存する。iPhoneには会話内の画像・本文を閲覧版として示し、
これらのローカルパスを外部共有URLとして扱わない。
