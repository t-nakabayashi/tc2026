# 手動走行による経路採取・編集

既存drive_mode_managerのJoy操縦を使い、共通自己位置とFAST-LIO点群から経路を採取する。
ノード自身は速度指令を出さない。5 mごと、25度以上の方向変化（最低移動1 m）、
停止ボタンの押下位置にwaypointを登録する。自動幅は確認候補であり、未観測部分は幅0とする。

```bash
ros2 launch route_survey record.launch.py output:=<新規採取ディレクトリ> projection:=<共通projection.yaml> use_sim_time:=true
```

実機はuse_sim_time:=falseとする。既存手動操縦・自己位置推定・FAST-LIOを先に起動する。
単独記録の既定はGNSS融合。ICP起動済みの場合は `localization_mode:=icp` を指定する。
Joy 0:採取開始、1:停止、2:信号停止、3:採取終了。番号はparams/default.yamlで変更できる。
走行切替はL1=4、PSは単体設定16・実機共通設定10。実機のJoy割当と設定を照合する。
FAST-LIOのpublish.scan_bodyframe_pub_enをtrueにし、body点群を配信する。GNSS融合モードでは水平化済み `/lio/odometry` も使用する。

保存先はfixed/waypoints.csv、route_config.yaml、projection.yaml、survey.jsonである。
CSVはroute_planner規定のLLH正本、高度空欄。survey.jsonには幅の観測理由・要確認フラグと
自己位置へ重畳した点群を保存する。1秒ごとに保存を要求し、専用ワーカーで書き込む。終了時にも最終状態を保存する。
保存中も位置・点群を受信し、保存要求が重なった場合は次回に最新状態をまとめる。
出力先は新規のみ許可し、既存経路を上書きしない。

```bash
ros2 run route_survey build_editor.py --survey <採取先>/survey.json --output <採取先>/editor.html
```

デジタルツインの航空写真・地図は--trial <地形ディレクトリ>で追加する。
--map-points <map座標XYZ.npy>で既存FAST-LIO点群も使用できる。原点整合は利用者が確認する。
HTMLは単体・オフライン動作。選択、位置ドラッグ、追加、削除、方位、停止属性、左右幅、
undo/redo、CSV/JSON/PNG保存を備える。編集は走行中routeへ自動適用しない。
編集したCSVをfixed/waypoints.csvへ配置し、走行停止後に経路を読み直す。

PC内HTMLはiPhoneへ自動配信されない。会話内の静止画像・本文を閲覧版とし、
iPhoneで編集する際はアクセス可能な共有先が必要である。外部公開は行わない。
詳細・検証範囲はdocs/設計と検証.mdを参照する。

本番として確認した経路の配置先は`src/route_planner/routes/<コース名>/`とする。
採取・編集の途中結果は別ディレクトリへ保存し、確認後にCSV・route_config.yaml・projection.yamlを
まとめて配置する。survey.jsonも確認履歴の原本として保持する。

自動幅は未観測部分を0・要確認とする。実機の縁石・センサ姿勢の校正と、採取経路の確認が必要である。

実機GUIの「実機／手動走行」は、FIX拘束付きグラフ地図へのICPを既定とする。
`/localization/pose_enu` の車体位置から経路を作り、GNSS生位置は比較用に別保存する。
地図の投影原点・姿勢を採取sessionへ引き継ぎ、保存CSVはGNSSモードと同じLLH形式とする。
「実機（融合）／手動走行」または `localization_mode=gnss` でGNSS＋FAST-LIO融合を選択できる。
ICP初期化は良好なFIXと方位、または `/initialpose` を使用する。初期化前は記録開始できない。
追跡中の地図照合が悪化するとLIO予測を記録し、ICP状態を要確認として保存し、自動幅は0とする。
LIOも途絶すると新しい点は追加せず、位置断中も「終了・保存」を受け付ける。
ICPの再初期化が必要な場合は手動で初期位置を設定するか、走行構成を再起動する。
GNSSへの自動切替や走行制御への追加介入は行わない。

`survey.json` の `traces.source` に方式、`icp_map_manifest` に参照地図を保存する。
比較軌跡の `fused` キーはICPとGNSS融合で共用し、各点の `source`・`mode` で区別する。
位置分散が0.25 m²を超える場合も要確認とし、自動幅は0にする。
ICPの共分散は工学的な参考値で、絶対誤差の保証ではない。
編集画面でGNSSと自己位置推定を個別表示し、時刻選択、FIX/FLOAT・衛星数・HDOP・
基線長・補正経過・方位精度を確認できる。受信履歴がないデータは補完しない。

実機共通sessionの`recorder_params`で、自己位置推定と一致するIMU取付位置・角度を読み込む。
body点群を車体へ変換してから車体傾斜を補正する。単独記録の既定値は水平・高さ0.6m。
傾斜配置の実機では生成されたrecorder.yamlを使う共通survey.launch.pyで起動する。
共通採取ではallow_auto_resume=falseによりL1を離しても手動モードを保持する。

GUIの「ルート記録」タブから開始・終了できる。
`/route_survey/command`（std_msgs/String）の `start` / `finish` を購読し、
コントローラーと共通の採取処理を使う。終了は自己位置途絶中も受け付け、
古い位置で終点を追加せず、それまでの記録を保存する。
`/route_survey/status` は保存中・保存先・保存結果・エラーを配信する。
「保存完了」は終了時の最新状態を書き込めた場合だけ表示する。エラー時は「終了・保存」で再試行できる。

## アスファルト・芝生境界の通行幅推定

GNSS融合モードでは水平化済みLIOの3D姿勢でIMU/body点群を短時間（既定6秒）蓄積し、
GNSS絶対補正を通行幅用の蓄積に使わない。ICPモードでは地図座標の車体3D姿勢と
IMU取付変換で配置・蓄積する。取付角度を重複して補正しない。ICP補正による局所的な
重なりのずれはあり得るため、幅は確認候補として扱う。
点群は2.5 cmボクセルで重複を除き、約5 Hzで処理する。時刻逆行・入力断・位置ジャンプ・
水平基準の再確定では蓄積を破棄する。平面基準は車輪中心のz=0ではなく観測から推定する。

局所平面からの高低差、粗さ、勾配と観測密度で連続した領域を判定する。
MID360反射強度は、明るい芝生等への拡張を拒否する補助情報として使用する。
基準候補の上限 `surface_max_seed_intensity=30` はMID360の設定値で、
反射強度だけでアスファルトと断定しない。芝生を走ったことを教師情報には使わない。
反射強度なし/不正、足元未観測、中央の車体通過範囲が不明な場合は幅0を保持する。
濡れた路面・塗装・低く刈った芝生等は別実験が必要であり、観測メタデータの
`review_required`を自動的に解除しない。

既定の車体半幅+余裕は `surface_margin_m=0.35`。保存するleft/rightは道幅ではなく
車体中心の横移動余裕。3×側方帯の全パッチが観測済みであることを要求し、未観測セルを
補間して広げない。GUIの「ルート記録」に左右の候補幅と、未観測・材質変化・段差などの
停止理由を表示する。保存済みルートの幅を自動で再計算しない。

反射強度の閾値は環境普遍ではない。平坦で反射強度が路面に近い芝生は境界を見逃す場合がある。
低い芝・濡れ・別舗装を幾何と反射強度だけで確実に識別できるとは扱わない。

## GNSS誤差に対する局所空間参照のサンプル

`tools/evaluate_free_space.py` は、ルート方向を参考にして、地表面の観測と現在の障害物から
進路候補を求めるオフライン評価用スクリプト。ROSノードや速度指令は生成せず、既存の
走行処理には組み込まない。実bagの各場面での候補評価と、位置・方位の誤差を与えた人工歩道での
閉ループ計算を別々に出力する。実行方法・出力・制限は [サンプルの説明](docs/free_space_sample.md) を参照。

`tools/evaluate_ground_thresholds.py` で同じbagの観測に対する閾値の感度を比較できる。
比較条件、芝生・段差を誤って許可する反例、およびJev等の外部モデルが未導入であることは
[閾値比較ツールの説明](docs/threshold_and_jev_evaluation.md)を参照。実機設定は変更しない。
